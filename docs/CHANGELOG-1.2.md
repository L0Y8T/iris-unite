# Iris Unite 1.2.0 变更说明

1.1 补的是失败处理与窗口适配。1.2 补的是**一直挂着没做的第三档：教学档**。

原来三档里只有速查与综述能真跑，教学档停在「配置与计划可预览」——`PROFILE_STAGES['p2-teach']` 有三条节点，`assertRunnable` 在运行期直接拒绝。这次把它做成了**学习模式**：先真实检索资料，再拆知识点、算依赖图、排学习阶段、出带答案与判分口径的自测题。

同一版里还加了**课前问诊**：跑之前模型先按主题问你几个问题，答案决定拆多细、从哪起步、跳过什么。

细节见 `docs/learning-mode.md`。

## 课前问诊：先问清水平与方向

同一句「我想学扩散模型」，零基础的人和做过生成模型的人需要的计划完全不同。不问清楚，就只能给出对所有人都差不多、对谁都不够用的计划。

配置面板里填一个主题 → 模型按**这个主题**出 4–6 个问题（问扩散模型就问「你熟不熟悉重参数化技巧」，而不是「你数学好不好」）→ 勾选/填写 → 答案存进配置。

| 设计点 | 做法 | 为什么 |
|---|---|---|
| 问题槽位 | 七个固定槽位：水平 / 目标 / 讲法 / 想覆盖 / 不想深入 / 已掌握 / 其它 | 答案要能落进确定的位置，模型不能自己发明维度 |
| 硬要求 | `水平`、`目标`、`已掌握` 三个必须有，模型漏问就补通用问法 | 这三项决定计划的基本形状；缺了等于没问诊 |
| 答案怎么用 | 以**要求**的形式追加在四处提示词末尾，写清它该改变什么 | 只丢进 JSON 材料里，模型容易当背景扫过去，最后还是按默认粒度拆 |
| 已掌握概念 | 直接并进先修检查 | 复用已有机械环节，不另写一套"跳过"逻辑 |
| 那次调用 | 发生在运行之前，不进科研账本、不占本轮调用上限 | 属于配置动作，不是本轮的一步；界面写明了这一点 |
| 归并规则 | 界面只交原始答案，槽位摘要由 `core/learning.cjs` 现算 | 渲染进程和主进程各写一份必然分叉 |
| 可复用 | 问题与答案一起存进配置，重开能看到上次问的 | 重跑、重新生成不必再答一遍 |
| 可追溯 | 自检固定一条「课前问诊已采纳」，没答过也写明计划按默认受众排 | 否则用户会以为这份计划已经按自己的水平排过了 |

顺带一个影响：`planVersion` 现在包含问诊摘要。同一份配置但答得不一样，是两份不同的计划，不能记成同一版。

## 为什么改的是语义，不是加新档

原设计（`docs/research-mode-design.md` §8）的教学档产出是「分章正文 + 例题算式校验」——一份完整教程。那是另一件事：需要术语表、章节覆盖模型、数值 AST 预计算与冻结渲染，堆进同一轮只会让两个产物都不完整。

而用户真正要的是**一份能照着学的计划**：先学什么、后学什么、每步学完能做到什么、怎么判断自己学会了。

所以三个环节 id 全部保留、语义重写：

| 环节 id | 原语义 | 新语义 |
|---|---|---|
| `teaching-outline` | 教学大纲 | 知识点拆解（模型只交「点 + 依赖」） |
| `teaching-sections` | 分节生成 | 分阶段计划（每个学习阶段一次调用，并行） |
| `teaching-examples` | 例题审查 | 自测题设计（每题带答案要点与判分口径） |

环节 id 不变意味着 `PROFILE_STAGES`、计划编译器的依赖表、`fanOutOf`、`baseCalls` 公式一行都不用改：C+5 / C+4 的调用数公式本来就是按这三个环节定的。

## 结构由代码算，文字由模型写

这是这次唯一的架构判断。

**问题**：让模型一次性写完整份计划，同一份知识点跑两次会得到两个学习顺序。顺序会变的计划不是计划，是一次性回复。而且模型把「学什么」和「先学什么」糊进同一段正文后，错了只能整篇重来。

**做法**：`core/learning.cjs`（新模块，纯函数）负责所有结构判断——连边、断悬空先修、按原始顺序 DFS 破环、拓扑分层、把拓扑序切成 C 个连续块、先修匹配、自测覆盖校验、确定性渲染。模型只回答三个问题：有哪些知识点、谁依赖谁、每段怎么讲。

可测性的回报：`tests/learning.test.cjs` 25 条全离线，亚毫秒级，覆盖破环方向、连续块满足依赖、确定性。

## 四个可选设计里做掉的三个

原本摆出来问的四件事，做了三件、明确不做一件：

| 设计 | 状态 | 说明 |
|---|---|---|
| 依赖图 + 拓扑排序 | 做 | 破环用 DFS 后向边，删哪条、为什么删都写进产物 |
| 自测题 | 做 | 每题三件套：题目 / 参考答案要点 / 判分口径；覆盖缺口由程序核 |
| 先修检查 | 做 | 用户声明「我已会 X」，命中的知识点不进主路径但仍留一道题确认 |
| 时间预算 | **不做** | 用户没有要求，编出来的学习时长是假精度 |

## 一个真实的界面 bug（改这次时踩到的）

教学档把阶段数从 2 改成 4，基准调用数从 7 涨到 9，而预算框还停在 7——计划预览直接变成一句「调用上限需 ≥ 本档基准调用数 9 次」，用户不知道该填多少。

修法不是猜数字，而是让界面自己走一遍：预算放进硬上限 → 编译出真实基准 → 收紧到「基准 + 可选深化」。**只在编译真的报出预算不足时介入**，用户自己填的更大预算不受影响。

顺带记一条：`refreshPlanPreview()` 拿的是**表单现值**编译，改 `researchDraft.budget` 不生效，必须改 DOM 输入框。第一次修就修错了地方，靠 UI 验收脚本抓出来的。

## 自检

教学档新增五条机械结论，进 `research-audit`：

- 知识点已排进学习阶段（结构问题清零）
- 先修关系可排序（破环之后无环，层数）
- 自测题覆盖知识点（`covered/total`，缺哪几个点名）
- 已有基础已排除（按用户声明排除了哪几个）
- 课前问诊已采纳（答过就写摘要；没答过也写明计划按默认受众排）
