## 1. 最终决策摘要

1. 保留三种产出类型：速查 `p0-query`、综述 `p1-review`、教学 `p2-teach`。P0/P1/P2 是沿用的 Profile 编号，不是优先级、模型等级或能力排名。界面优先显示中文名称。
2. 本期仅开放 `tier: "readonly"`。其准确含义是**不执行模型或用户提供的程序，不授予任意文件/命令/外部操作工具**。应用自身必要的检索、存储、解析、渲染和内置确定性校验仍可运行。否则连检索与保存记录都无法实现。
3. Profile、Tier、具体模型、模型支持的推理强度是四个不同维度。切换“更强”模型不能增加工具权限，也不能把速查自动升级成实验执行。
4. 新建P0/P1启用证据检索，P2默认启用；显式选择的旧资料可复用并记录来源。本轮新检索失败不抹去已选有效资料，但不得把旧材料说成本轮新获得。P2无资料教学与旧无检索P1使用各自未核验门禁，不冒充文献综述。
5. 三档均执行本地校验和发布门禁。正常完成时的基准模型调用分别为 P0 **3 次**、P1 **N+5 次**、有检索教学 **C+5 次**；可选复核、深化、修复、重试另计。检索为空等提前退出情形不强行凑满调用数。
6. 把“引用存在”“引用支持论点”“研究结论可靠”分开报告。机械核验能检查引用键、记录、摘录定位及结构；不能单靠两个引用键证明双方存在真实学术争议。
7. 静态模板、资源绑定计划与运行事件职责分开，界面、预算与执行共享同一套规则。不能只改stagesFor继续运行固定十阶段。
8. 每轮保留不可变配置、资料与模型输入清单快照。历史资料库可复用，但不能把上一轮记录静默当成本轮新检索结果。
9. 最终答案在校验后一次发布；过程面板默认折叠，显示公开的提纲、批评、证据与阶段记录，不展示或索取模型内部思维链。
10. 不把“几十秒”“1–2 天”“可投稿”“零幻觉”写成产品保证。工时与耗时由真实测量、接口条件、任务规模和验收结果决定。
11. 机械代理（§14.7）默认关闭、独立可选发布，仅产可机械检查的无损候选。主/机械分别记账并共同受总调用上限约束；不以recordId或词项集合声称语义保真，不在超时后接管正文。

### 3.2 本次观察到的实现缺口

- `validateConfig()` / `minCallsFor()` 按 `tasks.length + 5 + audit` 校验；关闭检索时仍计算证据提取调用。深化时 `budgetLeft` 只减去一次保留调用，存在最终生成与可选模型复核争用预算的空间。
- `runResearch()` 中最终生成的 `onFinal()` 先发往正文，`main.cjs` 在整轮完成后才用核验版替换。目标设计必须调整发布顺序。
- 资料库保留上轮记录；`knowledgeBlock()` 不同阶段按前若干条和不同摘要长度裁剪。模型未看到的材料可能存在于核验库中，不能仅因键在库里就认定模型的断言被支持。
- `KnowledgeBase.add()` 的 sourceId 去重未包含 source 命名空间；没有 DOI 时不同源的相同 sourceId 不应被合并。当前达到240条后停止添加，必须报告容量截断及本轮接纳结果。
- `citation.audit()` 在没有无法解析引用时返回 `ok:true`，包括无引用正文。作者年份式可疑引用会被统计但不按普通引用移除。不能据此展示“事实已验证”。
- `duet:model-list` 可在输入草稿改变 baseUrl 时回退使用同 ID 已保存密钥；保存连接时的保护不能代替模型列表请求自身的目标域绑定。多模型设置能力扩大前需要堵住此路径。
- 看门狗默认约10分钟无增量触发、每30秒检查；全轮超时固定20分钟。新 `wallClockSec` 不能只是写入配置而不影响这些主进程行为。

以上为源码评审发现，除后述离线测试覆盖的行为外，本次未声称逐项做了 UI 或真实网络复现。

## 4. 产品维度与权限模型

### 4.1 四个维度

| 维度 | 决定什么 | 不得隐含改变什么 |
| --- | --- | --- |
| Profile | 结果结构、任务模板、证据策略、阶段 | 工具权限、已保存用户问题 |
| Tier | 允许哪些执行与外部操作能力 | 模型名称、论断可信度 |
| 模型选择 | 每个活跃角色的 provider/model | 资料授权范围、预算上限 |
| 推理强度 | 该模型支持的 effort 枚举 | Profile、并发数、代码执行权限 |

“高强度”不表示“结果已核验”。不同厂商的 high/xhigh/max 不可跨模型当作同一刻度；UI 显示真实名称与支持的档位，不伪造统一推理能力分数。

### 4.2 Tier 的最终定义

| Tier | 能力边界 | 前置要求 | 本期 |
| --- | --- | --- | --- |
| T0 `readonly` | 模型仅产生文本/结构化数据；主进程做受控检索、保存与固定校验 | 明确文件输入与网络目标；模型无通用工具；不执行生成代码 | 唯一开放 |
| T1 `generate-only` | 明确生成程序、实验脚本、命令与运行说明；标“未执行” | 路径及产物约束；不自动安装依赖、不执行命令 | 后续 |
| T2 `local-exec` | 对用户批准的具体计划执行有限本地任务 | OS级隔离、限额、依赖与输入锁定、结果验证、进程树控制 | 后续 |
| T3 `training` | 受控训练与矩阵任务 | T2全部要求＋GPU/步数/检查点/队列预算 | 后续 |
| T4 外部调度 | 云或远程任务 | 凭据、收费、远程生命周期、结果可信链另立方案 | 超出本期 |

T0 不是“计算机不运行任何代码”。固定 JSON 解析、内置四则运算与引用匹配属于应用逻辑；运行模型提交的 Python/JS、shell、公式字符串 `eval()`，或可调用任意函数的表达式系统不属于 T0。

开启未来 T2/T3 的设置只表示用户愿意使用该能力，不能视为对任何新任务、目录、数据外传或收费的无限授权。实际执行必须绑定可审查计划和具体权限快照。

### 4.3 Profile 与 Tier 组合

本期三个 Profile 均为 T0。推演、实验设计、执行、审计作为未来独立 Profile，不写死固定调用数。实验设计可在 T0 讨论规格，在 T1 产出代码；执行类需要 T2/T3。教学将来若支持代码例题，应设计成显式的 T1/T2 扩展，不能以“仅教学”为由绕过权限。

## 5. 统一执行架构：配置、准入与执行分开

### 5.1 计划的三个层次与标识

纯函数可以接收外部状态的**值快照**，不应自己读取外部状态；原文将“输入包含状态”视为不纯的说法不准确。真正需要分开的是静态规则、一次运行的资源绑定和运行中的观察。

| 层 | 输入与行为 | 固定内容 | 不得做的事 |
| --- | --- | --- | --- |
| `compileTemplate(config, policy)` | 纯函数，无IO | Profile、节点槽位、角色需求、能力上限、分支、预算公式、发布条件 | 请求网络、读取设置、按在线状态删节点 |
| `bindPlan(template, catalogSnapshot, capabilitySnapshot)` | 纯函数，校验输入快照并绑定实际资源 | 实际模型与effort、连接版本、初始源访问模式、并发与大小限制 | 换成用户未选模型、提高预算、将暂时不可达当作永久事实 |
| 调度与观察 | 按绑定计划执行并追加事件 | 原计划不变；新增每次尝试与结果 | 回写原计划，伪装所有查询已执行 |

`planSchemaVersion` 是整数结构版本；`templateHash` 是模板和策略的规范JSON内容哈希；`planHash` 是绑定后计划的哈希。撤销用一个 `planVersion` 同时表示Schema版本、内容哈希和运行变化的约定。canonical JSON要求对象键排序、固定UTF-8编码、无NaN/undefined；数组顺序保留，集合先按规范排序；hash自身字段不参与hash。密钥、密钥哈希、认证头不进入这些对象，仅使用不透明credentialVersion标识。

模型目录与源能力快照有获取时间和状态 `known/unknown/stale`。缺Key、缺连接属于本地可知事实；可达性、配额余额、熔断是有时效的观察，不能在预检保证整轮可用。`capabilityDigest` 只用于记录快照身份，不替代完整的非敏感快照与逐请求结果。

UI根据模板显示正常路径、必需与可选节点和预算；启动后显示绑定计划及实际事件。静态规则测试以模板为准，状态与执行测试以绑定计划和事件为准，不能要求所有运行都执行完整静态节点列表。

### 5.2 准入顺序与运行中的配置变化

1. 在主进程验证IPC来源、commandId、对话权限与配置版本，读取配置草稿，不修改历史。
2. 迁移与本地Schema/语义校验；编译模板，确认主预算、机械预算、总预算、上下文和权限可满足。
3. 捕获目录/连接/源能力快照并绑定；预检只做本地检查，不默认付费测试模型或向全部源探测。
4. 必需模型不支持T0、角色不可用、上下文无法满足时返回可定位错误。部分源受限可按已选择的访问策略继续，并显示具体限制；不要求反复点击批准临时源失败，也不悄悄替换源。
5. 在同一对话锁内创建runId、冻结配置与绑定计划、登记主预算保留，再发布占位与开始计时。所有权检查和预算预约完成前不发任何模型请求。

运行中设置修改只影响新运行；撤销/清除凭据是例外，后续尚未发送请求必须失效，不继续用冻结的旧密钥。密钥仅在发送前按credentialVersion取得，明文不写快照；端点/协议/密钥版本变动返回 `connection_changed`，用户可按新配置新建运行。模型在服务端下线等竞态记为实际调用失败，不偷偷换更便宜或更强模型。

### 5.3 三档计划与条件节点

| 阶段 ID | 类型 | P0 | P1 | P2 |
| --- | --- | --- | --- | --- |
| `research-scope` | 模型 | 1 | 1 | 1 |
| `research-sources` | HTTP服务 | 启用 | 新版启用；旧无检索兼容例外 | 默认启用，可显式关闭 |
| `research-evidence` | 模型 | 有可用材料时1 | 有可用材料时1 | 检索开启且有可用材料时1 |
| `research-plan` | 模型 | 无 | 1 | 无 |
| `research-explore` | N个模型任务 | 无 | N | 无 |
| `research-screen` | 模型 | 无 | 1 | 无 |
| `research-refine` | 可选模型任务 | 无 | R，0…N | 无 |
| `research-summarize` | 模型 | 1 | 无 | 无 |
| `teaching-outline` | 模型 | 无 | 无 | 1 |
| `teaching-sections` | C个模型任务 | 无 | 无 | C |
| `teaching-examples` | 模型 | 无 | 无 | 1 |
| `research-final` | 模型 | 无 | 1 | 1 |
| `research-verify` | 本地 | 必需 | 必需 | 必需 |
| `research-audit` | 本地＋显式可选模型A | 必需 | 必需 | 必需 |
| `publish` | 本地提交 | 满足门禁 | 满足门禁 | 满足门禁 |

新增summarize/outline/sections/examples四个阶段族。N、C取自配置，不让模型增删；outline只填预先分配的C个章节槽位。后继阶段不得因收到更多章节而隐式增加调用。

```text
P0: scope → sources → evidence → summarize
P1: scope → sources → evidence → plan → explore[N] → screen → refine[R] → final
P2: scope → (sources → evidence，可选) → outline → sections[C] → examples → final
共同尾部: 本地验证 → 本地审计 → 配置的模型复核A → 发布前复验 → 原子提交
分支: 澄清请求 / 无资料 / 模型失败 / 停止 / 额度不足，均有明确终态或降级产物
```

空资料等分支直接生成本地范围/失败报告，不强行通过剩余模型节点；该报告仍经过最小格式、敏感信息与保存检查。门禁不能要求所有被条件跳过的节点都有成功产物。

**条件求值的唯一实现**（0.6.0 起）：`core/plan.cjs` 的 `CONDITION_OF` 声明每个节点的条件（`research-sources`=`retrieval-enabled`、`research-evidence`=`materials-available`、`research-refine`=`refinement-selected`），`activeNodes(plan, config)` 按配置求值，返回 `{active, skipped}`。运行器（`core/research.cjs`）、界面预览（`duet:plan`）、终审核对都调这一个函数，不允许各自再写一份判断。

条件只允许依赖**配置**（因此不会改变 `planVersion`）；外部能力（某个源此刻是否可用）只进 `deriveEffectivePlan` 的 `coverage` 与 `warnings`。这也是为什么运行器不再出现 `if (config.retrieval.enabled)` 这类散落判断。

### 5.4 多模型可见性与上下文可执行性

科研按Profile计划协作，不将普通协作的 `3N+2` 次调用叠加进每个节点。普通模式与科研策略分别记录，科研不得暗中调用GPT。

- P1计划广播给全部研究任务；独立初稿完成后screen接收每份结构化成果；批评包含对象、证据与具体要求；refine接收全部初稿的必要内容及批评；final接收全部候选的必要内容、保留/排除理由与修订。
- P2各章节接收同一术语表、提纲和证据；examples接收全部章节的例题及其必要背景；final接收章节和审查结果。章节可独立选模型。
- “可见全部成果”指输入包含所有约定的**有界结构化成果与必要证据**，不等于无限复制所有原始长文本。每份公开成果必须按共同Schema限制规模；每次调用保存实际输入包与依赖清单。
- 所有引用所依赖的原始片段必须直接进入当前生成/审阅调用的输入包；仅传一段其他模型的总结不算该调用已收到原证据。
- 超出上下文时先用确定性选材与字段投影保留全部必要依赖；仍超限则在发送前返回 `context_limit`，让用户缩小任务或明确换支持更大输入的模型。不能静默删去某模型批评，也不能用机械代理摘要替代必要原证据。

调用预算公式仅适用于上述有界输入和输出规模。批处理、追加读取、全量全文或额外语义摘要都需另一个显式计划与调用预算，本期不自动展开。

## 6. 证据、论断与最终答案的可检查契约

### 6.1 五层检查不混用

| 层 | 可检查范围 | 正确显示 | 不能声称 |
| --- | --- | --- | --- |
| E0结构 | 字段、枚举、ID、长度、依赖闭合 | 结构检查通过 | 文字正确 |
| E1记录 | S键对应本run的记录版本，标识可解析 | 引用记录可定位 | 出版商原文已读取 |
| E2片段 | 片段是已输入材料的真实切片，hash/偏移匹配 | 证据片段可定位 | 片段支持该断言 |
| E3支持关系 | 模型或人工判断直接/部分支持、相反、无关、条件不符 | 经模型审阅/未审阅/待人工确认 | 确定性证明、学术认证 |
| E4方法 | 评估偏差、设计、外推和充分性 | 具体方法审阅意见 | 自动同行评审通过 |

第一期硬门禁包含E0–E2及**已发现的**E3严重问题隔离，不承诺自动发现所有语义错误。A=0时E3可为not_requested；此类有定位但未全面语义审阅的草稿只能以 `completed_with_warnings` 发布。A成功也不能转称“事实已经证实”，只显示审阅范围和待审项。发布等级与运行是否完成分开。

### 6.2 片段由应用分配，不要求模型编偏移

SourceRecord以稳定recordId和不可变recordVersion定位；S键是run内别名。保留来源、sourceId、DOI/arXiv及版本、作者/年份（未知为null）、获取时间、sourceObservations和reuse来源。摘要没有读到就写metadata-only，不用题名推研究结果。

**在发模型请求前**，应用将已归一化文本按句/段或有上限的连续块切分并分配snippetId，保存 `recordId/recordVersion/normalizationVersion/start/end/text/hash/truncated`。start/end统一为JavaScript UTF-16 code unit、左闭右开，索引基于归一化后那一版本文本；hash对该切片UTF-8字节计算。测试包含中文、emoji、组合字符及不同换行，避免字节索引与字符索引串用。每片只来自一个字段与一条记录，不拼接两个来源冒充原文。

模型只能选择已提供的snippetId，不能填写“第6页第3段”或自造引文。题录片段仅支持资料导航/书目信息，不计入可支撑研究结果的usableSnippet集合；经验性source-claim不得只依赖标题字段。全文页码仅在实际解析到对应文件和页映射时存在，本期不承诺。片段用于定位，可保留比所示摘录更完整的邻近上下文，避免断章取义；E2不负责语义。

`publicationStatus`区分unknown/preprint/published/corrected/retracted，只有可靠来源标明时填值，未知不按域名猜。预印本和正式版关联studyFamilyId但不丢版本；DOI有效不等于文献未撤稿或质量可靠。

### 6.3 论断与块的最小Schema

正式类型约定在附录F。模型输出统一AnswerDraft或相应阶段Artifact；第一版是有界JSON树，不允许模型提交任意可执行HTML/公式宏。模型新claim/block的localId只需在该artifact内唯一；主进程接纳时以(artifactId,localId)映射为run内唯一不透明canonical ID并记录来源，不能要求几个独立模型自行协商不重复的claim-01。后继输入使用canonical ID；引用明确区分localRef与runRef，不猜字符串前缀、也不覆盖已有版本。

下例是主进程完成ID映射、合并系统字段后的内部Claim示意；写作者输出不得提交supportReview或自行指定另一个产物的canonical ID。

```json
{
  "claimId": "claim-01",
  "text": "在指定条件下，该研究报告了某项观察。",
  "kind": "source-claim",
  "evidence": [{"key": "S1", "snippetId": "sn-01", "relation": "proposed-support"}],
  "scope": "研究对象、任务和指标条件",
  "limitations": ["目前仅取得摘要"],
  "supportReview": {"status": "not_requested", "reviewedTextHash": null}
}
```

`relation`是作者模型提出的关系，不是审查结论。supportReview由主进程合并审查事件生成，不接受写作者自填supported。`kind`仅是模型/作者的分类，不能证明里面没有事实断言：source-claim、definition、derived-explanation、analogy、hypothesis、instruction、coverage-note都有明确展示与审查规则；“把结果句改标analogy/hypothesis”不能规避已发现的证据问题。

AnswerDraft块只支持heading/paragraph/bullet/table/example/reference-list/coverage-note；每段或表格单元列claimRefs、exampleRefs和必要条件。引用与例题由渲染器按这些ID生成，模型正文中裸写的S键、DOI或例题数字不得当成受信引用。引用列表由已发布依赖自动生成，不由模型自由填写。

为避免强约束导致文章无法阅读：普通连接语、教学讲解可保留文本，但不能标成机械验证覆盖；应用检查无法完备识别所有自然语言事实，报告必须说明这一点。P0尽量直接渲染已接收claim文本，减少最终改写；P1/P2允许final提出新/改写claim，但必须注册新版本、保留实际输入片段，旧E3状态失效。固定调用数不包含额外语义审查保证。

### 6.4 依赖闭合、隔离与文章完整性

以下属于硬错误：引用越run或越输入包、snippet不存在/hash不符、重复ID、引用依赖缺失、声明已审但文本hash不符、例题缺少必要条件。含任一无效依赖的最小语义单元整体隔离，不只删除键。

隔离后需执行**依赖闭包传播**：依赖它的结论、表格比较、章节摘要、例题解答及建议也标无效；循环依赖拒绝。标题/目录可确定性清理，其他内容不能自动重写来假装有逻辑衔接。结论引用被隔离时，不能保留“因此最优/因此无效”。

若根问题的必要回答单元丢失、结论与剩余内容不一致或唯一例题前提丢失，首版回退到本地证据不足/验证失败报告，保留草稿在过程区。若仅次要项被隔离且剩余回答自洽，可以有限结果和显式缺口发布；scope中的问题覆盖清单记录哪些已回答、哪些未答。是否达到用户科学目标不是机械定理，语义审查未覆盖时明确提示。

若有预留F额度，可让主模型修复一次，再跑E0–E2、依赖检查和必要审阅；无额度则不额外调用“整理版”。已知contradicted/unsupported的问题必须修复或隔离；不把review失败当作所有内容都无效，也不把review意见未经定位就当真实事实。

### 6.5 覆盖率按发布前后分别统计

所有计数以不同claimId为单位，不能一处说claim、一处按段落数。`draftEligibleClaims/publishedEligibleClaims`分别为草稿/发布结果中需要资料的论断数量；另列located、modelReviewed、supported、contradicted、pending和quarantined。一个claim有多个片段仍只计一次，引用次数另算。

对每项依赖，审阅结果绑定claimTextHash、snippet版本、reviewer及方法版本。分母为0显示N/A；不得先删掉全部不支持项，再只显示剩余100%而隐藏原稿隔离数。“引用齐全率”不是“正确率”。

“直接相关/间接相关/材料不足”说明支持关联；“仅摘要/单研究/跨条件”等说明限制；研究设计质量、被引数、模型确信程度不能混成一个强中弱分值。

### 6.6 分歧与共识

分歧对象记录topicId、明确命题、适用条件、双方position、source/snippet、studyFamilyId、可比性与语义审阅状态。不同记录不自动代表独立研究；同研究的预印本/期刊版、重分析或同数据集结果需要披露关联，独立性未知就写unknown。

E1/E2检查双方材料是否真实可定位；语义审阅判断是否同一命题、指标、方向、数据/人群与条件。**A=0或未审可比性时**只能写“候选差异，待核实”，不能作为已确认学术争议发布。共识也不能从“未找到反方”推出，默认表述为“本次材料中较一致的观察”，附范围。

只有单方材料时写“本次材料不足以判断是否存在分歧”；条件不同写“不可直接比较”。不要求每次综述都生成共识或反方，更不能强制模型为了通过双向规则编引用。

## 7. P0 速查与 P1 综述的最终规格

### 7.1 P0 速查

目标：快速回答“当前获得的文献材料对这个问题提供了什么信息”，用于初步定位资料，不做自动研究方向设计。

输入：用户问题、可选时间范围/语言/领域、检索源与查询上限、scope/evidence/summarize 三个模型选择。任务卡片、plan/screen/refine 配置不活跃；不能要求用户填写无用的 N 个任务。

流程与产物：

1. scope：产出研究目标、1–3个明确子问题、可检索关键词和范围假设。歧义不影响查找时采用保守解释并记录；明显对象冲突时请求澄清，澄清前不启动后续付费节点。
2. sources：真实检索、去重、质量/内容可用性判断，生成运行资料快照与检索状态。没有可用材料时提前结束。
3. evidence：只从实际送入的材料提取 source-claim，必须附 snippetId 与限制。若只有题录，产出“可进一步阅读的资料”，不得编结果。
4. summarize：默认3–8条紧凑要点，每条只表达一个主要结论，附材料键和限制；另给检索范围说明与资料列表，不强制分多章。
5. verify/audit/publish：本地结构与引用检查、问题覆盖检查、块级隔离；可选模型复核需显式额外预算。

正常、非空、有可用证据且无重试时3次模型调用。空库通常只发生scope的1次调用；证据提取后全部无关通常已花2次，随后本地生成证据不足报告，不再消耗summarize。允许实际调用少于3。

P0 可保留来源明确、条件完整的实用结论，但不新增没有证据的“最佳方案”、临床/法律/投资决策或未经验证的未来实验建议。用户要求推演时显示可切换到适合的模式，不自动扩大任务。

验收：没有调用 plan/explore/screen/refine；每个文献发现块通过E1/E2；无效块整体隔离；空/失败/取消区分；正文不是简单把引用删除后的残稿。时延只显示实际数据，不承诺几十秒。

### 7.2 P1 综述

定位：**专题文献综述草稿**，不是自动系统综述、全领域搜索或同行评审替代。

第一版保留当前十阶段骨架，但修改任务目标：按概念/方法/证据类型/适用条件组织材料，识别限制与待核实分歧，不强制寻找“创新点”和推荐实验。

- N为1–4项任务。可用模板为“概念与分类”“方法与比较”“反例与局限”“缺口与适用性”；用户可逐项指定不同模型和强度。同一个模型承担多任务也合法，UI 不把任务数当作独立模型数。
- plan 不能凭空增减任务ID；它将配置任务转成具体交付、引用范围和比较维度。缺少任务ID是实质错误，不可字符串化容错。
- explore 每份成果用结构化 source-claims、条件、限制、公开提纲表示。第一轮可独立生成，避免最早一份结果主导其他任务。
- screen 读取全部任务，提出有对象的严格批评：`targetArtifactId/issue/evidence/action/severity`。保留或排除的理由可追溯，不能只按文字流畅程度投票。
- refine 只修订被选择任务，每任务最多一次，受剩余预算限制。没有必要修改时跳过；没有反方证据时允许明确“不足以构成争议”。
- final 看到所有候选、批评、保留/排除理由与修订版本，输出唯一草稿。不得为达成“共识”而抹去少数结果和不确定性。

建议结构：研究范围；概念/方法地图；主要证据及可比条件；已观察到的分歧与替代解释；资料不足或未覆盖项；阅读路径；自动生成的资料列表。真实实验建议只在用户明确要求时以“未验证建议”输出。

P1验收不能是“争议必须双向，否则不通过”：真实材料可能没有争议。应是“凡被发布为争议的块满足双方证据和可比性条件；否则明确材料不足”。类似地，不要求每篇论文都被引用，要求说明选入理由与未覆盖范围。

### 7.3 与旧 P1 行为的兼容边界

原提案要求“升级后行为等价”与新版更严格证据门禁不能同时绝对满足。最终决定：**保存与历史显示兼容；新运行的安全与证据规则按新版执行。** 迁移保留模型、任务、预算、深化开关；旧答案原样展示并标原验证等级，不倒写为新版已核验。旧无检索配置不悄悄开启网络，也不悄悄转成另一个Profile；运行前给明确兼容状态。

## 8. P2 教学：学习结构与例题验证

### 8.1 教学输入与产物

输入增加 `audience/prerequisites/learningGoal/chapterCount`，默认面向有基础但未系统学习的读者；不要求用户先回答问卷才能开始。默认C=2，可在2–4间设置。章数是预算参数；模型不能自行把4章拆成12次调用。

流程：scope界定学习目标 → sources/evidence（默认启用）→ outline给出先修依赖与术语表 → sections生成C份章节草稿 → examples一次集中审查例题与误解 → final整合 → 本地验证 → 发布。

每章包含：目标、必要定义、直观解释、适用条件、例子、易错点、短练习。内容按需要采用，不强制每章重复完全相同的小标题。提纲中记录概念依赖，后继章节不先使用尚未介绍且没有提示的术语。

支持每章单独选择模型；可先用一个章节角色作为默认，再在高级设置展开覆盖。outline/examples/final分别独立配置，不能用一个含糊的 `teach` 字段代替所有教学角色。

### 8.2 事实、定义、类比与推导

- 来自论文的经验性结论、方法效果、历史归属必须关联材料。定义在检索开启时尽量引用材料；定义约定与本文教学记号可标为“本教程约定”。
- “这是一种直观类比”标记只需在该类比块明确显示一次，同时说明对应关系和失效边界，不必每句机械重复“这不是事实”。
- 类比不能用来证明原命题；类比后的经验性判断仍需证据。不得把“像河流”之类句式搜索当作能完整识别所有隐喻的验收器。
- 形式推导注明假设和定义。文献引用不能证明推导步骤有效，模型审阅也不等于形式化证明。没有接入证明器时显示“解释性推导”。
- 数值例题必须标“教学构造数据”，不能用随机编出的数字冒充真实论文结果。

### 8.3 T0数值例题：收紧到能实际实现的范围

第一版只做**精确有理数算术**，不同时承诺浮点容差、任意统计和符号代数。允许节点为const/add/sub/mul/div/pow-int；percentToRatio、ratioToPercent和msToSec等转换通过固定规则实现。十进制字符串转为有理数，不用JS浮点假装精确。

每道例题含exampleId、构造数据标记、givens、assumptions、AST、expectedDisplay、unit和rounding。叶节点引用givens的值ID，不能另写一组相似数字。应用检查变量集合、类型和单位，再独立计算；这只证明**所给表达式的数值**，不证明AST正确表达题意。

| 限制 | 首版契约 |
| --- | --- |
| AST | 最多100节点、深度20；拒绝共享循环对象、未知属性和未知操作 |
| 数字 | 单个十进制/整数文本最多64字符，小数位最多18，不接受科学计数法、NaN或Infinity |
| 幂 | 整数指数绝对值≤16；0的非正整数幂按不支持处理；运算前估算输出位数 |
| 资源 | 分子/分母各最多4096bit，累计操作100次；超过即unsupported，不先构造无限大BigInt |
| 舍入 | places为0…8，统一half-even，最终用有理数确定性舍入；expectedDisplay与规范显示精确比较 |
| 单位 | dimensionless/probability/percent/count/s/ms；加减需同单位，显式转换后可比较；乘除首版只允许无量纲参与或同单位相除 |
| 容差 | 用户/模型不能自设巨大tolerance让错误通过；首版不接收tolerance字段 |

不执行eval、Function、Python/JS脚本、用户函数、网络、文件IO或任意循环。单位复合、任意统计量、微积分、矩阵、模拟和证明器超出首版；可给符号解释并标未计算验证，不生成看似已算对的数值答案。

`teaching-examples` 是一次模型审查/修订，不是本地计算器。它需收到一次**预计算报告**（本地零模型调用），修正草稿后再次本地计算；final只按exampleId放置冻结例题及结果。final若修改题设、AST或结果，产生新例题版本并撤销旧审查，重新验证。没有F额度且修改无效时隔离该例题，依赖它的解答/结论同步隔离。

最终数值由渲染器插入，例题块不能同时附一份模型自由手写、数值不同的答案。正文其他数字不自动纳入“例题已验证”；实际文献结果走证据映射而非构造数据算术。AST题意正确性、推导完整性与单位含义仍需语义审阅，未审不得宣传“例题全部正确”。

### 8.4 无外部资料教学

用户显式关闭检索后，不执行sources/evidence，不生成S键，不输出自称基于文献的经验性结论。正文标“以下为通用概念讲解，未进行外部资料核验”，给定义、构造例子、推导假设与自测问题。算术验证仍可运行，但它不验证整个概念讲解的正确性。

检索失败不自动转无资料教学。若用户本轮已明确选入有效旧资料，可仅基于这些资料给有界讲解并披露新检索失败；否则进入证据不足。改无资料教学需用户主动选择的新运行。

### 8.5 教学验收

检查概念依赖、术语一致、层级与范围；经验性论断有材料定位；类比与条件独立标识；练习与解答一致；数值例题有计算来源与验证状态；最终文本未偷偷修改已验证数值。学习效果用固定任务的人工评估检查理解与迁移能力，不用“字数多、章数多、引用多”替代。

## 9. 调用、时间、HTTP与并发预算

### 9.1 公式、预算桶和全局上限

N＝P1任务1–4；R＝深化0…N；C＝教学章节2–4；A＝显式模型复核0/1；F＝实际主模型修复尝试；E＝实际主模型传输重试尝试；M＝机械代理尝试。计数对象是应用适配层**已派发的模型尝试**，不是厂商账单里的全部内部计算。

| 正常路径 | 主模型基准B | 追加主模型 | 机械模型 | 总派发 |
| --- | --- | --- | --- | --- |
| P0有可用材料 | 3 | A+F+E | M | 3+A+F+E+M |
| P1有可用材料 | N+5 | R+A+F+E | M | N+5+R+A+F+E+M |
| P1旧无检索兼容 | N+4 | R+A+F+E | M | N+4+R+A+F+E+M |
| P2有可用检索材料 | C+5 | A+F+E | M | C+5+A+F+E+M |
| P2显式无检索 | C+4 | A+F+E | M | C+4+A+F+E+M |

空材料、澄清、取消与失败会提前退出，B不是最低实耗。P1固定五次为scope/evidence/plan/screen/final；P2固定五次为scope/evidence/outline/examples/final。HTTP检索和本地检查不计模型尝试，但有自己的请求/时间/资源开销。

**三个限额同时约束：** `budget.maxCalls`限主模型，`mech.maxMechCalls`限机械模型，`budget.maxTotalCalls`限两者合计。每次派发同时扣对应桶与总桶。首版总上限24，主桶上限24，机械桶0…4；配置必须满足 `maxTotalCalls >= maxCalls + maxMechCalls` 且 `maxTotalCalls <= 24`。因此启用机械不能绕开24次总上限，也不能挤占原主模型承诺额度；要增加机械额度先明确提高总限额，不能后台自动增加。

界面显示“主模型6/9 · 机械2/4 · 合计8/13”，不可把8与9比较。初始默认机械关闭，总上限等于主上限；新增机械后的总限额需在保存前可见。数调用不是金额硬限制。

### 9.2 预约、派发与失败账本

每次模型请求使用唯一 `modelAttemptId`；HTTP用 `httpAttemptId`；两者都不是runId。尝试状态分为reserved、dispatched、succeeded、failed、cancelled_before_dispatch、cancel_requested、outcome_unknown；具体错误另存，不靠一个cancelled掩盖是否已发。

1. 在主进程串行临界区验证run非终态、deadline、后续必需保留及三桶余额，建立预约；全局provider并发位另外预约。
2. 取得并复核连接版本；将派发账本持久化后调用适配器。一次尝试只能派发一次。持久化失败不发送。
3. 预约且可证明未派发时可释放；派发后失败/超时/用户取消仍计数。崩溃发生在记账和网络发送之间时保守记outcome_unknown并保留配额，不能证明免计费。
4. 每次重试都新建尝试，不能在SDK或适配器内部隐藏重试。若CLI内部传输重试不可观测，明确应用计数范围与账单未知，不能宣传精确计费上限。
5. `requiredReserve`只包含**尚未预约、尚未派发**的必需节点；预约转入已用后不再重复保留。可选调用的准入条件为：对应桶与总桶扣除已用、其他预约和后续必需保留后仍足够。

P1 N=2、A=1、主上限9：screen结束已用6，final/audit需保留2，最多深化1项。不能只减final的1次，也不能把已派发的explore再保留一次。

模型网络重试与内容修复各受每节点0/1次限制，默认0；全轮主桶和总桶仍是最终约束。节点自身的首次请求、重试、修复共享总资源期限，不能每次重新获得完整300秒。结构修复不等于支持关系审查。

模型复核如配置了A，必须预留其1次调用；它不是保证成功的承诺。复核失败保留明确unavailable状态，能否发布按§14的门禁；不得因已配置就填passed。无模型修复额度时不允许临时加一次“最后整理”。

### 9.3 HTTP预算与检索公平性

`maxQueries/maxRequests/maxRecordsPerSource/maxRecordsPerQuery/maxRecordsPerRun/maxRetriesPerRequest`分别控制逻辑查询、实际HTTP派发、返回资料规模。PubMed搜索与摘要/题录子请求、分页、重定向（如允许）、重试分别计HTTP；取消后已发送请求不退回。

按“查询轮次×所选源”建立任务矩阵，轮转分配请求额度，不能让某源的连续重试耗尽其他源第一轮查询的机会。重试只能用未保护的剩余请求位；不足完成PubMed两步时标incomplete，不把只有ID列表当完成。

每条查询保留actualStatus与源响应计数；容量240、每源和每查询上限均为接纳规则，不是“已检索全集”证明。停在上限保留已取得材料与未执行矩阵项。首版不自动扩词、追引用或下载全文；新策略需显式预算。

### 9.4 期限与取消的可实现含义

全轮期限从准入成功进入queued时开始，包含等待、限流、机械调用、所有重试与本地检查。使用单调时钟计算进程内期限并保存UTC开始/deadline用于重开与唤醒核对；系统时钟变化或休眠后重新检查，不据此增加额度或自动恢复。

单模型节点资源期限、单HTTP请求期限、全轮期限共同取最早者。机械诊断有自己的短期限，且只能使用剩余全轮时间。全轮超时/停止后禁止任何新模型调用，包括诊断和“保存前润色”。

硬期限的工程含义是“不再准入新工作并尽快发出停止请求”，不是保证第三方服务当秒停止、取消计费或OS在任意阻塞下精确回收。网络响应读取、解析、哈希等任务必须有大小界限，必要时放受控worker，避免主事件循环被阻塞而无法处理停止。首版关闭程序时不暗中继续科研；未结束运行恢复后标interrupted。

统一记录 `deadline_exceeded/user_cancel/provider_timeout/context_limit/heuristic_stall/connection_changed` 等原因。UI显示“本轮时间上限15分钟，取消后的服务端状态可能未知”，不承诺每轮固定耗时；停止后不要因为本地超时就继续进行一个新的远程诊断。

### 9.5 Tokens、费用与隐式重试

用量按modelAttemptId记录provider回报，累计型流式usage更新最后有效值，不能将同一次请求的每个累计值反复相加。缺失为unknown；总览列已报告覆盖次数，不将缺失填0。输入字符估算与实际token分开。

只有价格版本、币种、计量口径已知才显示估算；CLI订阅额度不等价API费用。并发、缓存、内部推理tokens与服务端重试会影响实际账单。没有支持计费拒绝的提供商接口时，不宣称有绝对金额硬上限。

### 9.6 并发和可选失败

模型默认并发2，上限4，主/机械合计占同一provider和应用并发限制；HTTP使用按源共享发送队列。预算、并发位、会话锁都是不同资源，不能用一个余额代替全部。

必需分支失败时不进入依赖节点；可取消兄弟分支并保留已完成成果，主运行failed。可选深化失败时保留对应初稿并标warning，只要剩余门禁满足仍可生成。即使希望“尽量给答案”，也不把缺失必需任务的半套结果伪装成完整P1。若未来支持缩小任务集，必须作为新计划/新运行展示，不能事后改N使账本看似正确。

### 10.2 字段规范

- `profile/tier` 必须白名单匹配。本期除readonly外拒绝执行，不能静默降级再显示原Tier。
- `choices` 的 choice 必须具备有效 provider/model/effort，核对目录及能力；只有活跃节点必需角色才要求可用。关闭audit时无需保持其旧模型在线。
- P0 的有效输出角色为summarize；P1/P2为final。主进程不再无条件访问 `choices.final` 填写writer。participants从活跃计划取，不扫描所有隐藏配置角色。
- P1验证tasks 1–4且ID唯一、长度符合现有边界；P0/P2不要求tasks有值。教学章选择只允许当前1…C章，未覆盖章继承teachingSections。
- `allowRefinement` 必须显式布尔；R≤min(N,maxTasks)，每任务最多一次，额度不足按可选策略跳过。
- maxCalls为正整数且不低于当前活跃计划的必需调用数、不得超过统一上限；未知/非有限/负值一律拒绝，不用隐式字符串转换执行。
- 墙钟建议允许60–1200秒；单模型期限不得大于全轮上限。具体上下限采用统一策略常量，并向UI暴露。旧配置缺少时间字段映射为原20分钟上限，而不是无提示缩短到示例15分钟。
- 年份为null或整数，`yearFrom<=yearTo<=当前年`；未明确年份的资料标unknown并在筛选报告说明，不假装满足年份过滤。原代码无yearTo，新增必须落实到查询或本地过滤。
- P0/P1的新配置 retrieval.enabled 不得为false；P2关闭检索需 `allowGeneralTeaching:true`，否则返回可定位的字段错误。
- 长度、节点数、输出字符与资料包上限在主进程执行，统一值见附录F；前端限制不是唯一约束。
- maxTotalCalls为整数，必须覆盖maxCalls与maxMechCalls之和且不超过24；所有派发同时检查对应桶与总桶。
- selectedRecordRefs为用户明确选入的recordId/recordVersion/runId列表；复用时保留原来源与获取日期。sourceAccessPolicy按源只允许key-required/allow-anonymous，未激活或失效Key不自动回退匿名。
- monitor.stallPolicy首版只支持warn-only；硬期限一直有效，不存在另一个隐形启发式中止定时器。maxModelRetryAttempts/maxRepairAttempts首版每节点各0/1且默认0，均受总桶与节点资源期限约束。
- mech按§14.7.4验证：默认关闭、choice可空，triggers只接受四个白名单值；开启需有效Choice、非空triggers、1…4次机械额度及足够maxTotalCalls，maxAttemptsPerNode固定1。关闭时机械额度0且不预检其模型。无论开关，错误提供字段路径，未知关键字段不静默忽略。

### 10.3 严格校验与有限容错

校验分四步：版本迁移 → 结构归一化 → 语义校验 → 活跃资源预检。不要在渲染时悄悄修复并保存，也不要把所有错误都称为模型不可用。

可归一化：展示用列表中的单字符串转单项数组、首尾空白、大小写规范且明确的S键。必须记录字段路径和归一化规则版本。

不可容错：任务ID错配、引用依赖丢失、权限变更、模型/provider不一致、负预算、无效公式、含未知执行指令的对象。不得先去掉所有非字母数字再把恶意或错误键“修成”另一个合法键；只接受明确定义的引用语法。

结构化输出能力通过适配层声明为 `native-schema | json-mode | text-validated`，无论提供商声称哪种能力，本地都再次验证。不能因为当前Codex支持output-schema，就假定DeepSeek及所有自定义连接能执行同等Schema约束。

## 11. 迁移、历史、存储与删除

### 11.1 v2/v3迁移与v4结构冻结

v4尚未发布时，在同一设计Schema中补齐字段并设 `configSchemaRevision:1`；正式发布后不允许同一个version无记录改变语义。运行Schema、配置Schema、协议事件Schema各有独立版本，不能一处version=4就假设所有存储都同版本。

迁移是纯函数：读取原对象深拷贝，输出新配置和报告；读取历史不保存。配置编辑采用revision乐观锁，避免两个窗口后保存者无提示覆盖。未知高版本保留原对象可读，不执行、不默认降到v4。

| 原状态 | 新运行规则 |
| --- | --- |
| v3标准研究 | 映射p1-review/readonly，保留角色、任务顺序、effort与深化开关 |
| maxCalls | 保留主上限，maxTotalCalls同值，mech关闭；不加钱、不降低原预算 |
| 旧perSource | 映射源内与合并查询上限以保留旧截断语义，记录legacyMapping |
| 旧monitor | 保留enabled，仅控制启发式；新硬期限按已存原上限或原20分钟 |
| v2orchestrator/reviewer | 先按原升级链映射，再迁移v4；无效字段保留在legacy原件并报告 |
| 已停用模型/旧预算不足 | 历史可查看；新运行前定位角色/缺额，不自动替换或涨额 |
| 新教学/summarize字段 | 非活跃时可空；首次切Profile填草稿并显示真实模型，保存前校验 |
| 旧无检索P1 | 保留兼容标记；新生成仅为“无外部核验的研究草稿”，不走需要E1/E2的有证据发布分支 |

旧无检索兼容分支不生成S键、不显示验证通过，允许结构化讲解/假设与方法讨论，经验性结论作为未外部核验陈述标识。它仍需T0、结构、敏感信息、预算门禁；不是为了兼容重新开放旧权限漏洞。用户编辑为新版有证据P1时移除兼容标记，开启检索需显式可见，不从互不相容配置中静默猜意图。

### 11.2 身份、快照与凭据

- conversationId定位对话，userMessageId定位问题；runId定位一次生成尝试，parentRunId可指向被重试版本；answerVersion只在发布成功后在同一问题下递增。
- nodeId定位固定阶段槽位，如research-explore--task-1、teaching-sections--chapter-2；artifactId+artifactVersion定位公开成果；modelAttemptId/httpAttemptId定位一次派发。撤销同时用attemptId表示整轮与单调用的歧义。
- 每run保存configSnapshot、template/plan及其hash、目录/非敏感能力快照、policy/prompt/app版本、输入清单、账本、节点结果、mechCalls与mechOutputs。机械关闭时后两项仍为0/空数组。没有保存模型采样与服务端状态时只能承诺输入/产物可追溯，不能承诺逐字重现模型输出。
- 密钥与Key哈希、认证URL、CLI登录材料不落入快照。可保存credentialVersion与受限连接身份；已撤销Key不得被旧run重新取用。

同对话同问题多run并存；已发布答案的S键只解析其run快照。可保留对话库作索引，但本轮采用哪些旧记录必须显式选入并标reuse。旧轮不可变指的是对象版本不自动覆写，不是永远不可删除。

### 11.3 旧历史不能凭空补成新快照

已有v3资料库是对话级可变文件，无法确定某旧回答当时看过哪几条。迁移时可以冻结一份 `legacy-import` 副本并记录“导入时资料”，**不能**称其为旧run原始输入。旧消息保留原文本和旧核验等级；S键只能按legacy映射查看并显示不确定性。

旧回答的S1不因新轮重新检索而改指。无法找到旧映射时显示“旧版引用资料缺失”，不自动用当前S1补齐。后续导出各run用独立命名空间或生成全局引用映射，不能直接拼接同名S键。

### 11.4 单写者提交与崩溃恢复

首版一个dataRoot只允许一个主进程写者；第二实例聚焦已有窗口或以只读方式打开，不能各自写conversations.json。新旧程序不要同时写同一目录；创建带app/schema版本的运行锁，过期锁需核对进程和恢复状态，不能只凭PID相同认定同一实例。

继续使用内容文件＋manifest时，**manifest是唯一发布事实源**：先写新版本答案/报告/资料对象，校验hash，写临时manifest并flush，在本地文件系统上使用经目标Windows验证的同目录替换提交。对话列表和索引从manifest派生；禁止“manifest已发布、消息JSON仍未发布”两份独立真值。

若选择数据库事务实现同样契约，可替换内部存储，但不引入数据库与文件双重提交。Windows文件占用/杀毒软件导致替换失败时有限重试，不先删旧manifest；失败保留旧已发布版本，写可恢复失败记录。多文件分别rename不是跨文件原子事务。

停止/超时/发布竞争在同一run锁内串行判定。提交前检查停止标记和deadline；一旦提交成功，completed成为终态，晚到停止返回“该版本已完成”，不把已发布改cancelled。若停止先获锁，则不得提交正文。崩溃发生在提交后、通知前时重开按manifest恢复已发布结果，不重复付费调用。

### 11.5 重试幂等与不确定请求

重试先做本地预检，不删旧答案、不新增用户消息、不更改旧roundId。commandId在主进程与持久化run记录唯一绑定；相同commandId重复调用返回同一run/结果，不重复派发。新一次主动重试用新commandId/runId，保留parentRunId。

应用重启后在途请求记interrupted/outcome_unknown；首版不自动续跑或重放。用户明确重试会重新花调用额度，UI提示旧尝试可能已计费。后台窗口关闭/应用退出按既定停止策略处理，不留下未告知的远程模型任务假装可本地回收。

### 11.6 删除、容量和隐私

默认不上传运行数据；不可变版本服从用户删除。删除对话时先禁止新任务并取消活跃run，等待本地写者退出，再更新引用索引；共享对象只在没有任何保留manifest引用时清理，保留中的导出/阅读任务持短读租约。不能只删索引留下大批敏感草稿。

缓存、原始模型输出、草稿、诊断包均有可查看的容量与清理策略。初始建议每run保存文件总量上限20MiB、每对话100MiB，达到上限停止新增正文/原始记录并提示清理；这是应用本地存储限制，不自动删除用户历史。用户可显式调高，测试包含磁盘满、只读、长路径、非ASCII路径和文件占用。

离线文件被手工改动时hash失效并隔离，hash不是防恶意篡改认证。导出可追溯不等于第三方可信签名。导入包若未来开放，需zip路径/链接/容量/Schema校验；本期只导出，不能暗中把导出包当可执行插件。

## 12. 模型适配、连接与上下文

### 12.1 能力目录

每模型目录项至少关联可用effort、上下文/输出上限（未知则标未知）、结构化输出方式、流式与用量支持、是否具备工具调用能力及本次是否禁用。provider兼容同一协议不等于支持同一请求字段。机械角色使用相同能力结构，另记录受测候选Schema、测试版本与结果；不把“稳定、高质量、廉价”作为无证据布尔标志。native-schema/json-mode/text-validated均仍需本地校验。

推理强度控件使用离散刻度拖动条，键盘方向键可移动，Home/End定位；每个刻度显示提供商真实档名，模型名在收起菜单时仍常驻，如用户目录中的“GPT-6.1 Sol”。不要硬编码一个未来所有设备均有的模型ID或把不存在的档位显示为可选。更换模型后旧effort不兼容时在草稿中提示改用支持档位，保存前可见，不静默升级到昂贵档。

### 12.2 就绪与凭据边界

只预检活跃计划中的模型与源。预检包括本地配置完整、连接启用、CLI可定位与登录状态可判断、密钥存在或明确允许无密钥。真实“测试连接”需说明会发请求；普通保存配置不无故消耗模型调用。

调用密钥只在主进程解密，绑定已保存连接ID、协议、规范化目标origin/base-path与凭据版本。用户修改端点时，禁止模型列表、测试连接、实际生成任一路径自动沿用旧密钥；需重新明确绑定。保留现有HTTPS/本地HTTP规则与重定向限制；不能只在saveConnection里做保护。

检索凭据与模型凭据分开，不把OpenAlex Key放入提示词。密钥撤销后尚未派发的请求不得继续用旧版本；主进程IPC校验可信frame、固定操作、长度与commandId，不向renderer暴露encryptedKey或任意fetch。所有错误、URL、日志和导出剔除Authorization/api_key等，诊断只保留可公开的错误类别。

### 12.3 上下文预算

原问题、当前Profile约束、任务身份、证据片段与批评是必要输入。不能把整个历史、全库和所有模型全文无上限复制到每次调用。

输入包按§5.4生成：非必要材料可按明确策略裁剪，必要片段、全部约定的公开成果和批评不能静默删除；仍超限则发送前context_limit。可引用集合与实际输入一致。分批提取、额外摘要和追加读取都需另一个显式计划，不能隐藏在单个evidence节点免费加调用。

跨模型传递限于本轮授权的公开材料。涉及用户指定文件时只读其显式选择内容，不因为工作区路径存在就允许扫描整个工作区。源摘要、用户附件和模型输出一律作为不可信数据，不可通过其中的命令开启工具、改endpoint、加预算或访问本地路径。

## 13. 检索：访问模式、查询、限流与状态矩阵

### 13.1 上游规则是有时间的外部依赖

保留此前核对结论：OpenAlex官方弃用说明与认证页对受限匿名访问的文字并不完全一致，不能把“永久免费匿名足够”或“所有请求必需Key”写成永久前提。产品支持用户配置Key、受限匿名模式及准确错误状态；移除靠mailto提高OpenAlex额度的旧承诺。[弃用说明](https://help.openalex.org/api/deprecations/)、[认证说明](https://help.openalex.org/api/authentication/)。本轮未重复真实接口联通测试，不将网页说明当作已验证的当前配额。

Crossref提供公开REST和礼貌访问选项；公开元数据不等于摘要/全文无版权条件。[REST说明](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[访问选项](https://www.crossref.org/documentation/retrieve-metadata/)。arXiv API手册建议连续请求保留间隔；PubMed/E-utilities的HTTP限额要覆盖搜索及题录子请求。[arXiv手册](https://info.arxiv.org/help/api/user-manual.html)、[NCBI使用要求](https://www.ncbi.nlm.nih.gov/books/NBK25497/?report=reader)。不将当前文档里的配额值长期硬编码成服务承诺。

发布前对实际适配版本做少量有日期的联通验收；用户未授权的情况下不代注册、发激活邮件、充值、下载全文或自动付费升级。

### 13.2 查询AST与按源适配

scope输出统一QuerySpec：conceptId、明确词项/同义词、AND/OR/NOT节点、字段与时间条件，或可解释的keyword-search。每源编译器声明哪些语义可保留；不支持的布尔/字段条件标queryDegraded，记录变换。相同关键词集合不能证明语义相同，A AND B与A OR B禁止当作等价。

若关键排除条件无法在源侧实现，先按明确规则取结果并在本地可检查字段上过滤；无法核对时显示限制，不静默声称条件满足。不得把一个通用AND/OR字符串发送四源后称为等价系统检索。

模型给不出有效AST时可用原问题的规范关键词检索，标fallback且不作布尔等价承诺；不增加隐形模型修复。原问题含敏感信息时不自动将整个历史作为查询，源请求只包含本次明确检索范围。

PubMed只有题录时标metadata-only；增加摘要获取会增加HTTP与解析，不属于免费隐藏步骤。首版不抓任意URL全文；有本地用户资料的扩展另设授权、解析与费用规则。

### 13.3 发送队列、重试和响应边界

应用级按源/目标origin共享队列，所有真实HTTP发送经队列，包括子请求和重试；避免仅在search入口节流。等待可取消，归属runId，熔断共享但每run记录实际跳过原因。零命中不是故障，不触发熔断。

429使用合法Retry-After或有上限退避，等待不得超过本run剩余期限；401/403和400不盲重试。最多每请求1次重试并受总HTTP预算约束。熔断状态具有冷却/半开/最近成功时间，不能把其他对话的失败记成本轮已查过。

固定检索适配器只请求内置审核的HTTPS端点，模型不能改host/path或提供认证参数。本期不开放任意检索源URL。重定向默认拒绝；若官方流程确需，逐跳验证允许域、协议和凭据边界并计请求，不能带Key跳到新目标。

响应流**边读边限额**，不等完整解压后才检查。首版每HTTP解码后文本最多2MiB、总压缩响应也设上限、JSON深度64，XML禁止DTD/外部实体与任何隐式网络解析；超限中止并记录，不把畸形内容修成看似成功。固定适配器可按证据修改上限，但配置/策略需版本化。XML正则不能被当作通用完整解析器。

论文元数据URL仅供查看，先做URL解析和协议校验；外链只允许预期http/https，不接受file/javascript/data等。自动HTTP请求永不跟随摘要内指令或把record.url当任意下载任务。来源数据的HTML清理与长度约束在渲染前仍执行。

### 13.4 不再用一个coverage枚举混合全部含义

对每个“queryId×sourceId”项保存三组信息：

- accessMode：key/anonymous/unconfigured/blocked；认证与限制独立记录。
- execution：pending/queued/dispatched/succeeded/failed/skipped/cancelled/budget_exhausted，含所有HTTP尝试与错误。
- content：rawCount、acceptedCount、usableSnippetCount、metadataOnlyCount、dedupCount、truncated。

`coverage`只描述已请求矩阵的执行覆盖：complete/partial/unavailable/not_requested；是否预算截断和访问受限用独立字段 `budgetLimited/accessRestricted`。complete表示配置矩阵被执行且无失败，不表示查尽文献或所有结果有摘要。一次零命中可执行成功，usableRecords仍为0。

| 情形 | 最终可说什么 | 不可说什么 |
| --- | --- | --- |
| 全部执行成功，零命中 | 本次范围和查询未获得匹配资料 | 不存在相关研究 |
| 部分源失败，有可用材料 | 有限覆盖结果并列具体缺失项 | 所有源全部完成 |
| 只有题录，没有可用片段 | 资料导航报告 | 已总结未读结果 |
| 片段都有但与问题无关 | 没有获得足够相关证据 | 凑一篇无关材料综述 |
| 全部请求失败/无访问权 | 检索未完成 | 查无文献 |
| 取消 | 已停止，保留已取得的过程快照 | 无缝改成成功答案 |
| 请求/条数/时间到上限 | 已执行项和未执行项分别列出 | 穷尽检索 |

P0/P1与启用检索的P2在没有可用证据时默认进入evidence_insufficient并输出本地报告。若用户在本轮开始前明确选入了可用旧资料，即使本轮搜索全部失败，仍可仅基于所选资料生成有界草稿，标明freshRecords=0、reusedRecords与原获取时间、coverage=unavailable；不能显示本轮检索成功。未明确选入的旧库不能自动兜底。P2不能因失败自动转无资料教学；旧无检索P1按其专门兼容分支，不与失败混淆。

### 13.5 去重、版本与选材

sourceId命名空间是(source,sourceId)；优先规范DOI与arXiv ID，版本关系与studyFamilyId保留。相似题名仅标候选重复，不强行合并；同研究多个版本不自动算多份独立支持。记录跨源field冲突与各自observation，不默认被引数更高的题录更正确。

选材兼顾相关性、内容可用性、源覆盖和时间条件，策略版本固定。资料少于某阈值不代表“无证据”，关键是是否有相关可用片段；多少片段足够支持科学结论仍是语义问题。截断与排序可追溯，未明年份、撤稿/更正状态均不自动补值。

### 13.6 凭据存储、IPC与预检

`settings.sourceCredentials[sourceId]`保存加密Key、credentialVersion、updatedAt、verifiedAt及对应验证版本；sourceId必须在内置枚举中，不能接受__proto__等任意键。安全存储不可用时拒绝静默明文落盘，可允许用户明确选择仅本进程会话保存。Key变化清除旧verifiedAt，“曾验证”不等于现在可用。

源凭据IPC只提供save/clear/status/test等有界操作；renderer只得到hasKey、验证日期与状态，不得到encryptedKey、Key或任意fetch能力。验证IPC发送者来自可信应用frame，校验sourceId、长度和commandId。test明确会访问对应源并计独立诊断HTTP账本，不自动消耗科研run预算；不能在每次打开设置时测试四源。

凭据只绑定固定源目标，不跨源或跨协议复用，源端点由适配器策略决定，不受模型或IPC自由输入控制。诊断、URL、事件、导出全部脱敏。受限匿名是否尝试由保存的sourceAccessPolicy决定；Key未激活时不自动回退匿名而隐瞒认证错误。

本地预检不能预测配额耗尽和网络故障；实际结果按§13.4记录。设置页“已配置/曾验证”与运行中的“本次请求成功/失败”明确分开。

## 14. 运行状态、监控、发布与机械代理

### 14.1 状态机与等待输入

```text
命令校验（失败不创建run） → queued → running → verifying → publishing
                                                    → completed / completed_with_warnings
运行分支终态：needs_clarification / evidence_insufficient / failed / cancelled / interrupted
非终态收到停止：stopping → cancelled（先于提交获锁时）
```

只有runId是整轮身份；节点pending/queued/running/succeeded/skipped/failed/cancelled，模型尝试有§9的独立状态。关闭窗口不是完成，终止也不是自动通过验证。

scope判定必须澄清时输出1–3个短问题与已做解释，run以needs_clarification结束、释放未发配额、停止定时器；不挂着远程任务等待用户。用户回复产生关联的新消息/新run，预算重新显示，不冒充原轮免费续跑。普通低风险歧义可采用已记录假设继续，不无限弹澄清。

evidence_insufficient可以保存本地报告但不是科学答案发布；报告字段区分reportVersion与publishedAnswerVersion。若曾有旧答案，保留旧答案为当前可选版本，失败报告不覆盖它。

### 14.2 事件、重连与快照

事件含eventSchemaVersion、runId、单调sequence、type、nodeId、可选taskId/modelAttemptId/httpAttemptId、status与timestamp；预算事件同时提供主/机械/总三桶已用、预约和限额。明确注册 `mech_handoff/mech_output_rejected/mech_candidate_accepted`，不是仅靠提到通用适配器就算已经存在。

主进程先注册订阅，再交付带lastSequence的持久化快照；前端按sequence去重并只应用快照后的事件。乱序缓存有界，发现缺口请求新快照；旧run事件不更新当前run正文。无需持久化每token，但阶段、派发、停止、验证和发布事件需要可恢复记录。

并行进度显示任务数与各自状态，不把阶段序号当耗时百分比。阶段总数来自绑定计划和分支状态；条件跳过明确标原因，不伪造跑满100%。

### 14.3 监控不负责自动扩权

monitor.enabled仅控制启发式重复/停滞提示、可选深化建议，硬预算/期限/输出上限始终生效。waiting reason是调度器的可观测事实：queued、backoff、provider_inflight、local_work；无文本时不能证明模型内部long_reasoning或故障。

规则监控可以提示“暂未收到新内容”，不能据此立刻换模型。达到节点超时时先取消对应尝试并释放本地并发位；服务端状态可能unknown。是否有剩余原节点资源与全轮资源决定是否还能重试，不能每次接管重置超时。

本期默认不自动更换主角色模型。机械代理只处理§14.7严格列出的辅助任务，不是“主模型超时后让小模型写完整答案”的后门。

### 14.4 停止与远端不确定性

收到停止后在主进程run锁内写停止标记，取消排队/HTTP/适配请求及本地worker，禁止新派发；已完成产物保留，已发配额不回退。迟到响应记录为迟到/丢弃，不覆盖节点成功版本，不转completed。

本地子进程控制须证明归属并处理子进程树，不能仅kill一个PID便承诺全部停止；远程模型无法证明停止时标cancel_requested/outcome_unknown。UI可以说“本地已停止接收，远端状态未知”，不能永远转圈等待不可确认的远端。

提交和停止的先后按§11.4定义，发生在同一串行临界区；提交后晚到取消不回滚已发布内容。关闭程序、断网、休眠、凭据撤销分别记录，不混成同一“用户停止”。

### 14.5 发布门禁与语义审阅失败

每种输出有一份明确门禁清单：grounded-answer、unverified-teaching、legacy-unretrieved、local-report。不能让无资料教学满足不存在的E1/E2，也不能借兼容分支绕过T0、结构和预算。

有证据答案发布须满足：run未取消/超时；必需节点成功或定义的降级；账本自洽；E0–E2与依赖闭包通过；例题数值与版本通过；正文/资料/报告可持久化。未知模型能力不当作已禁用工具。已发现关键语义反例、伪造或与来源相反的内容不得因警告状态继续原样发布。

模型review返回结构化问题 `targetBlockId/claimId/issueKind/snippetRefs/assessment/proposedFix`，依赖ID和片段先机检；不接受无法定位的“整篇错误”自动删光正文。问题可标supported/partially_supported/contradicted/insufficient/uncertain，审阅完成与认为支持是两项指标。

- review调用失败或结构无效：review=unavailable；若本地门禁通过，可按草稿等级completed_with_warnings发布，不伪造passed。
- 有定位的contradicted/insufficient：隔离问题块及依赖，或在已有F预算内修复。review只提建议不自动修改正文。
- review意见自身不确定：显示uncertain，争议结论等需要确认的项不以确定语气发布；保留原材料供人工查阅。
- 任一修订改变claim文字或证据版本，旧review哈希失效；同一次review不能同时当作对它提出的修订已再次审查的证明。

A=0或并未逐claim审完时，发布必须带未全面语义审阅提示。completed意味着工作流完成，不意味着科学事实已认证。质量门禁保持可执行范围，不承诺自然语言事实识别完备。

### 14.6 缓冲、发布与草稿

final/summarize的模型输出先进入有界草稿缓冲；主界面显示阶段、实际模型、三桶预算与停止。校验后通过唯一manifest原子提交正文与报告，再通知前端。验证后如需改动，再形成新版本和新报告。

过程区可查看公开提纲、批评、输入资料和未核验草稿，默认折叠，明确其状态；不展示内部思维链。最终答案复制/导出只取已提交版本；如开放草稿复制，使用明确的“复制未核验草稿”入口。

### 14.7 机械代理：保留可选能力，撤销不可证明的语义保证

#### 14.7.1 定位与实施顺序

mech是默认关闭的文本模型辅助角色，M5a独立可选里程碑，不阻塞三档核心发布。不承担正文写作、E3语义审查、发布判断、任意工具操作；所有主流程门禁与关闭时一致。开启后只能增加**显式获准的**机械桶额度与可能耗时，不能宣传必然更快、更便宜或质量更高。

本轮撤销“同recordId、相同数字/作者就能机械证明摘要保真”“同词项集合就能证明查询等价”的判断。确定性验证不了的一般自然语言摘要、语义改写、错误原因推断，不能交给mech后标可信。

#### 14.7.2 四个触发器的有限职责

| trigger / 输出类型 | 允许的候选 | 确定性接纳条件 | 不允许的扩展 |
| --- | --- | --- | --- |
| on-repair-candidate / candidate | 对固定Schema的有限JSON Patch，仅结构修复 | path白名单；原字符串/数字原样；只选已有ID；不删必需字段；本地完整Schema再验 | 改事实、补引用、改单位/符号/极性、用“支持”替代“反对” |
| on-bulk-summarize / summary | 名称兼容保留，实为无损字段投影计划 | recordId完整覆盖预定集合；主进程从原输入取字段/原文；必要片段不丢 | 自由撰写“总结”、新组合结论、删掉否定或条件 |
| on-query-compile / query-plan | 在既有QuerySpec上的序列化候选 | 保留AST的操作符、字段、词项和结构；语义由受信源编译器决定 | 新扩词、AND改OR、仅比较关键词集合 |
| on-stall-diagnose / diagnosis | 从现有故障事实选择可显示的建议标签 | errorId存在、错误事实不变、动作在固定策略允许集合；不自动执行 | 自称确认网络/模型内部故障、改变stopReason、重启任务 |

自然语言diagnosis备注最多200个Unicode字符，只显示“模型建议”，不能写成系统判定。summary/query-plan是兼容旧名的受限结构，不把其作用宣传为语义压缩；如果受信编译器已能零调用完成，直接使用，不为“用了代理”额外调用。

Patch只允许在同一规范字段路径上使用受信别名映射、列表单项化、已声明的大小写规范；不能在两个claim之间交换同样存在的字符串/引用。任何新增值必须由主进程从同一原字段确定性得到，不接受代理自由填写。projection的记录集合禁止重复或缺项，必要字段由调用节点策略决定，代理不能删去限制/否定/条件字段。

修复候选一旦被接纳可形成原节点产物的新变换版本，保留原尝试和patch，不强制再让主模型复述一次，避免隐藏增加F。若需要改内容，转主模型F请求，额度不足则失败或隔离；机械输出不能用来证明内容正确。

#### 14.7.3 超时、取消与接管条件

on-repair在本地有限修复失败且原输出已完整接收时触发；on-bulk/query只在预定义辅助槽位触发；on-stall只在节点已超时并取消本地尝试后提出诊断建议。排队、HTTP在途、backoff和正常provider_inflight期间不得因为无文本抢跑第二模型。

node的资源期限已耗尽则不得重试该node；可选诊断是计划中的独立辅助节点，有自己不超过30秒的额度，受剩余全轮期限约束。必需节点失败后run可短暂完成该辅助节点再写failed，但一旦进入任意终态不得新派发。全轮deadline/user_cancel/credential_revoked时不调用mech。若远端是否终止未知，诊断不恢复原任务，也不并行接管事实产出；用户可以看已完成材料或显式新run重试。

#### 14.7.4 配置、额度与回落

```json
{
  "mech": {
    "enabled": false,
    "choice": null,
    "triggers": [],
    "maxAttemptsPerNode": 1,
    "maxMechCalls": 0,
    "timeoutSec": 30,
    "outputPolicy": "candidate-only",
    "onInvalidOutput": "return-to-original-policy"
  }
}
```

enabled时choice使用与主模型相同的provider/model/effort结构并通过T0预检，不假设存在provider=local。triggers必须非空且只含上表枚举；maxMechCalls为1…4并显式提高maxTotalCalls满足§9；maxAttemptsPerNode首版固定1，timeoutSec为1…30且不大于剩余全轮期限。

每node最多一次mech调用，不允许每trigger各循环一次来绕过上限。mech失败后回到**原节点已定义的失败/修复策略**：有F/E剩余额度与节点时间才可派发主模型；否则隔离或结束。禁止无条件“回落主模型再试一次”，禁止mech失败触发mech。

#### 14.7.5 事件、审计与回归

每调用保存modelAttemptId、原inputHash、允许patch路径或投影字段、输出hash、accepted/rejected及原因；有损或越权候选拒绝，事件为mech_output_rejected。无论接纳与否均计机械桶及总桶，成功也不放宽发布门禁。关闭时mechCalls=0、mechOutputs=[]。

“关闭时回归”指在**同一目标版、同一注入目录/时钟/数据**下关闭mech与不进入mech分支的正常路径，在标准化UUID/时间后语义事件和产物相同；不要求与0.6.0逐字/事件序列相等，后者已因迁移/门禁变化不可能。不得将文档同步表的“已完成”当作实现通过。

#### 14.7.6 可选发布门槛

必须验证四类越权候选被拒；否定词/条件/单位变化被拒；主/机械/总额度任一不足均不发；节点期限和全轮期限不重置；旧迟到响应不覆盖成功产物；mech不可用不修改Profile或证据状态；源查询语义无损；关闭回归在规范化事件下成立。

“小模型适用性”只作基于受测Schema的能力说明，记录测试版本和样本，不设一个未经验证的“稳定高质量”布尔值。若无真实可验收场景，保留契约但不开放按钮，核心三档照常发布。

## 15. 界面与交互规格

延续Iris Unite既有简约桌面布局、黑白中性色与鸢尾花品牌。本文不重新引入演示模式，不因新增科研能力把主界面变成工作流控制台。

### 15.1 入口与配置层次

输入区保持“普通协作 / 科研”模式入口；科研旁常驻Profile名称、当前输出角色的具体模型名和强度。如由多个角色参与，显示“综述 · 3个模型”，展开后列角色映射；不能笼统写GPT而隐藏真实模型。

科研设置按下列顺序：

1. **目标**：速查/综述/教学三项与一句产出说明。采用平行选项，避免命名成初级/中级/高级。
2. **模型分工**：先显示常用预设和当前具体名称，角色覆盖放高级区；P1第二层任务允许各自选不同模型。
3. **资料范围**：源、时间、查询上限、是否复用已选资料；OpenAlex等凭据缺失状态在对应源旁显示。
4. **预算**：基准/上限/已保留，墙钟上限、并发。必须在常见窗口高度可见。
5. **高级设置**：深化、可选复核、章节模型、重试、检索细项、监控。

配置页使用可滚动内容区和固定底部操作区；保存/取消和预算摘要不能被长任务表单推到屏幕外。940×660最小窗口、常见缩放比例下均需可操作。切Profile保留各自草稿，未保存退出有明确处理；没有请求进行时可即时切换，不弹多余确认。

### 15.2 模型与强度控件

每个活跃角色一行显示“角色—模型具体名—effort”，选模型菜单支持提供商分组、搜索、连接状态。强度拖动条离散吸附，鼠标拖动与键盘操作结果一致；指针悬停不能是唯一查看档位的方式。

## 16. T0权限与不可信输入的发布要求

### 16.1 必须从实现证明的边界

当前 `providers.cjs` 可见read-only sandbox参数与“禁止工具”的提示词，不能据此写“工具已从能力层禁用”。提示词不是权限控制；只读目录也不等于不能读取用户文件或运行无写入程序。

后续实现必须核对实际CLI版本及可用配置，禁用通用命令、文件工具、继承MCP/插件及任意网络工具，或使用已验证不具备这些工具的文本适配路径。执行环境使用最小权限与空/专用cwd，不继承用户项目配置中可能启用的能力。若现有CLI无法提供可证明的T0边界，发布说明必须承认限制；严格T0要求未满足前不能宣称该通道已通过此项验收。

这里没有给出未经验证的某条CLI开关作为万能修复。应以对应实际安装版本的官方能力与对抗测试为准，不能借机开启更高权限解决兼容问题。

### 16.2 输入边界

- 论文摘要、模型互评、用户附件都可能含“忽略指令、读取密钥、运行命令”等内容；数据包与阶段指令分离，能力由主进程白名单决定，输入内容不能改权限。
- 检索目标固定为适配器认可端点，跳转按策略处理。不把论文摘要中的URL当作自动下载命令，不允许任意本地文件路径从模型输出进入读取接口。
- 渲染保留现有HTML清理与CSP；新增Markdown块、公式、表格、外链仍走统一安全渲染，不直接拼接不可信HTML。
- 中间记录可能包含用户未公开研究方向，默认仅本地保存，跨模型共享范围在启动前可见；不为了排错上传整个工作区或完整对话到新提供商。

### 16.3 证明方式

构造含诱导命令、文件路径、伪工具调用、端点改写的摘要与模型输出，确认无shell/文件扫描/任意网络操作发生；测试不同工作区配置与CLI继承场景。对模型本身是否服从指令的测试不能代替对系统没有暴露危险能力的检查。

本期文档修改不执行这些对抗任务；这是实现完成后的发布门槛，不是当前已通过的认证。

### 16.4 M0必须先做的通道可行性探针

严格T0不能只写成最终发布条件却不提供工程决策路径。对实际使用的Codex CLI版本、DeepSeek文本API、自定义连接分别记录：工具可见列表/请求字段、是否继承本机配置/MCP/插件、可否禁止工具、子进程与网络边界、Schema与usage支持。

Codex优先尝试该安装版本官方支持并经本地证明的文本/无工具路径；不要在方案里虚构“某flag肯定能禁用全部工具”。若无法关闭或隔离继承工具，当前CLI通道不满足严格T0，停止该通道的新科研准入并给明确原因。现有历史仍能阅读，其余已验证通道仍可用，但不能自动替换用户指定角色。

可选的API文本适配需用户已有对应凭据或明确配置，不能假设桌面订阅/CLI登录可直接转为API计费或复用其凭证；不能无提示把“Codex集成”变成另一个付费产品。若产品必须保留现有CLI登录能力，而严格T0在其版本无法落实，应先做权限方案评审，不把无法满足的功能承诺带入M1排期。

本期T0/T1的真正安全差别不是能否在文字里出现代码：T0教学可含明确未执行的短代码示例；T1是把可运行程序/命令作为正式产物交付的产品能力。二者都不授权执行。生成一段代码不等于运行，read-only参数也不能独立证明工具完全关闭。

## 17. 结果溯源与复现：执行能力之前必须建立的契约

### 17.1 与文献核验的关系

可复用“提取—解析—核验—隔离—自检”的思想，但实验结果需要独立类型和验证器。DOI是记录身份；日志字段是带单位、切分、运行环境与变换的观察值，不能简单字符串替换。

为后续建立 `ExperimentSpec → RunManifest → ArtifactRegistry → MetricRecord → VerificationReport → ExportBundle`。先通过固定合成数据和用户导入的真实结果测试此链，再开放代码执行。用户已有真实日志即可做结果整理与草稿，**不必为了写实证论文强制先内置执行器**。

### 17.2 实验规格与产物注册

ExperimentSpec保存研究问题、假设、独立/控制变量、基线、数据授权与版本、切分策略、指标定义、停止条件、重复与随机种子策略、硬件和资源限额、预先指定的比较/筛选方法。

ArtifactRegistry由主进程注册有限目录中的文件：artifactId、runId、相对路径、内容类型、大小、SHA-256、生成节点、代码/输入/环境版本、createdAt、finalized状态。模型只引用artifactId，不能提交任意绝对路径供核验器打开。

必须校验解析后路径仍在运行根目录，处理 `..`、绝对路径、符号链接/Windows junction与重解析点。finalized后不可静默变更；哈希变化使旧报告失效。有限文件大小、行数、JSON深度和类型白名单，防止验证器本身被日志拖垮。

### 17.3 指标语义

每项MetricRecord至少包括：`metricId/artifactId/locator/name/value/unit/datasetId/split/aggregation/seed/checkpoint/codeVersion`。locator采用可验证JSON路径或JSONL行与字段，不能靠“搜索到同名字符串”判断。

区分比例/百分比、best/final、validation/test、每次运行/跨种子汇总、宏平均/微平均、延迟均值/分位数。95%准确率与0.95相等只在单位已声明时转换；0.95秒和950毫秒也必须显式变换。

派生数保存输入metricId、固定运算与舍入规则。例如提升2个百分点不同于相对提升2%。均值/标准差/置信区间要记录有效样本数、算法与缺失值策略，不能由模型看两行数字口算后写成已核验结果。

正确率字段来自真实日志，只证明“该日志记录了这个值”，不证明数据无泄漏、评估代码正确或运行确实按规格执行。代码版本、数据切分和方法审查仍需要独立证据。

### 17.4 异常与统计约束

部分失败的实验不能从汇总中无痕移除；报告计划数、成功数、失败/排除原因与缺失项。重复种子、重名run、断点重启累计时长、只保存最佳checkpoint等情形有明确规则。

不得把同一测试集反复调参后选出来的best_test_acc当作无偏最终比较。参考CIFAR10字段时尤其需要区分历史记录习惯与目标科学协议；优先验证集选型、保留独立测试评估，或如实披露探索性反复评估。

“重复3次取中位数”“消融最多8组”可以是产品资源默认值，不能作为所有科学问题充分的统计依据。重复数、误差估计、功效/样本量与比较方式依研究问题及噪声决定；工具只做有假设的计算与记录，不承诺自动决定科学充分性。

### 17.5 复现包先于执行开放

最小导出包包含：规格、配置/模型/提示版本、代码与环境锁或清单、输入数据标识/哈希、命令参数、种子、运行manifest、原始指标、派生指标规则、校验报告、图表生成规格与说明。默认排除API Key、CLI凭据、私有数据原文及绝对用户路径；有许可的数据通过明确选项纳入。

本期可先做文献研究包：问题、查询记录、题录、获准保存的片段、论断映射、模型公开成果与验证报告。导出不保证外部服务未来返回完全相同记录，只保证本次材料可定位、包内版本自洽。

## 19. 后续执行、训练与图表能力

> **方向变更（用户明确要求，2026-10 起）**：本文最初把「执行」列为本期排除项。用户明确要的是**执行平台**，因此执行能力从"排除"改为"分阶段交付"。边界不是取消了，而是换了一种划法：

> | 阶段 | 形态 | 隔离 | 状态 |
> | --- | --- | --- | --- |
> | E1 受控执行 | 只跑随程序分发的模板脚本，模型/用户只能填白名单参数 | 不需要 OS 隔离（代码不是模型现写的） | **已交付**（见 §19.5） |

### 19.5 E1：受控执行（已交付）

实现位置 `core/exec/`：

| 文件 | 责任 |
| --- | --- |
| `templates.cjs` | 模板注册表：脚本名、依赖清单、参数 schema、产物与指标声明、超时区间。参数校验是纯函数，越界直接报错不夹值 |
| `env.cjs` | 按依赖清单哈希建独立 venv，装完锁指纹复用；不碰系统 Python（本机系统解释器里有互相牵制的残包） |
| `runner.cjs` | 起进程、逐行日志（截断到 1500 行 / 单行 2000 字）、超时与取消都杀进程树、收产物并算 SHA-256 |
| `manifest.cjs` | 运行记录结构与校验；完成态缺指标/缺产物/退出码不符一律判为不完整 |
| `claims.cjs` | 数字溯源：`[E1]` 标记必须指向已完成的运行，正文里的实验数字必须能在该运行指标里找到（百分数与小数互认，整数要求精确相等） |

关键设计：

- **运行目录隔离**：每次运行一个独立目录，cwd 就是它，产物只能落到 `artifacts/`；环境变量清空 `PYTHONPATH`/`PYTHONHOME`。
- **manifest 是唯一证据**：界面、后续引用、核验都读它，不读模型的话。状态为 done 的必要条件是：退出码 0、`metrics.json` 可解析、模板声明的产物齐全。
- **参数不算实验结果**：`metricTable()` 会剔除 `params.*`，避免"轮数"被当成指标。
- **未实现模板显式禁用**：`digit-cnn`（需要 PyTorch 与 MNIST 下载策略）在模板表里标 `unimplemented`，界面禁用、运行期拒绝。

已实测（本机 32 核 / RTX 4090 Laptop / Windows 11 家庭版）：digits 数据集随机森林，测试集准确率 0.9639 / macro-F1 0.9634，训练 0.518 s，产物混淆矩阵与 `metrics.json` 均带 SHA-256；从建 venv 到出结果共 35.2 s。

### 19.7 执行 driver 层（可插拔）

`core/exec/driver.cjs` 是"怎么跑"与"跑什么"的分界。接口：

```
id / name / description          标识与说明
isolation / network              隔离与网络的**实际情况**（界面直接显示，不许美化）
supports(template) => boolean    这个模板该不该由我跑
prepare({template, dataRoot, onLog})                    准备环境，返回任意上下文
run({template, params, dataRoot, env, timeoutSec, signal, onEvent, conversationId})
```

当前只有一个 driver：`template-python`（`isolation: 'none'、network: 'allowed'`——这两项是实测事实，界面照实写）。模板用 `driver` 字段声明自己要哪个 driver；如果某个模板要求 `wsl-container` 而本期没有，`resolve()` 会明确拒绝并说明，**不会偷偷退回本机执行**。

因此 E2 的接入成本只是新增 `core/exec/driver-wsl.cjs` 并注册进 `DRIVERS`：运行期、IPC、界面、运行记录格式都不需要改。

### 19.6 实验数字门禁与执行预算（E1.5，已交付）

**数字门禁**：科研流程的最终答案里，实验数字必须指回本对话中状态为 done 的运行记录。

- 最终环节的输入材料带上 `experiments` 字段（`claims.referenceBlock` 生成的 E1/E2… 清单，含参数与指标）；没有完成运行时这句话会明确写成「不得出现实验数字」。
- 发布前机械核验（`research-verify` 之后的 9.5 环节，不消耗模型预算）：
  - `[E9]` 指向不存在或未完成的运行 → 删掉标记；
  - 正文数字在该运行的指标与参数里找不到 → 改写成 `〔未核对：88.8%〕`；
  - 结果写进 `reply.experiments` 与终审自检项「实验数字可核对」，不通过则 verdict 为 `attention`。
- 百分数与小数互认（97.3% ↔ 0.973），整数要求精确相等（否则「准确率 1」会被宽松地匹配到 0.97）。
- `F1`、`top-1`、`E1` 这类词内数字不会被当成数据（正则前置断言）。

已实测（`tests/exec-gate-check.cjs`，真执行 + 假模型服务）：真实数字 `11.200641 [E1]` → 门禁通过并绑定 1 处；换成 `999.999999 [E1]` → 门禁拦下，正文变成 `〔未核对：999.999999〕`。

**执行预算**：独立于模型调用预算的一本账（`core/exec/budget.cjs`）。

| 项 | 默认上限 | 说明 |
| --- | --- | --- |
| 本对话运行次数 | 20 | 防止一个对话无限重跑 |
| 今日运行次数 | 50 | 跨对话的总闸 |
| 今日执行时长 | 7200 秒 | 防止长时间训练把机器占满 |

超限时 `duet:exec-run` 在**启动前**拒绝并说明是哪一项到顶；执行面板顶部常驻显示三项用量。模型调用预算（`core/budget.cjs`）与它互不占用。

### 19.1 执行MVP的放行条件

只有§17的规格、验证、导出、预算通过后，才实现有限T2。建议首个场景是受控目录中、已有依赖、无网络的CPU测试任务，不承诺固定5分钟适用于所有问题。

必须具有：独立最小权限运行身份/OS隔离、只读输入、受控输出目录、网络默认关闭、禁止宿主凭据继承、环境变量白名单、依赖锁定、进程树归属、时间/CPU/内存/输出/磁盘上限，以及停止后确认所有子进程退出。Windows可评估Job Object等资源与进程生命周期机制，但它本身不等于完整文件/网络沙箱。

“允许python.exe”只能限定入口，不阻止它读用户文件、联网、起子进程；命令白名单、独立cwd、`windowsHide`、提示词均不是独立安全边界。无法落实OS边界的版本只能保持T1生成不跑。

执行计划在授权前具体化：代码/脚本hash、输入标识、目录、依赖、联网目标、最大资源和预计产物。方案改动扩大权限或费用需重新授权；修复代码不能借用旧授权越界运行。

### 19.2 训练与队列

T3增加epoch/step/GPU时长、显存、并发、checkpoint、恢复点、异常loss/NaN/OOM、数据切分与验证指标规则。指标平台期默认建议，不让模型因“效果不够好”无限加实验。

中止动作区分“不再启动新任务”“给当前任务检查点后停止”“立即结束进程树”，UI不能统称停止导致用户误以为GPU已释放。掉电、休眠、重启后的恢复策略显式记录；未知硬件状态不假设安全。

### 19.3 图表

实测图由已注册、已验证指标和确定性绘图规格生成。图中每条曲线/表格单元可追溯到run与字段；记录缺失值、误差带定义、样本量、单位、坐标尺度与聚合方法。未完成实验不能画成完整平滑曲线；不同训练长度不偷偷补点；比较相对提升与百分点要标清。

模型可以选择图型、解释已核验数据、提出待检验解释；不能生成伪造实测曲线、补不存在的实验点或把教学示意当真实数据。概念图和示意曲线可独立存在，但必须标“示意，非实测”，不得进入Results实测面板。

图表渲染器可作为受信固定组件，与运行任意生成脚本区分。若仍通过Python/外部进程绘图，也需要相应执行策略，不能借“只是画图”绕过Tier。

### 19.4 其他CS能力的合理顺序

先做导入真实结果、字段核验与复现包；再做受控程序测试、已有许可数据上的基准、受控数据管线、性能分析；最后扩展训练和消融矩阵。顺序可按用户任务调整，但不能跳过权限、预算、溯源前置。

单机可完成的科学工作取决于任务和资源，不应一概称为玩具。工具应披露数据规模、重复与限制，而不是用机器类型代替研究价值判断。

## 20. 论文与导出的现实边界

| 目标 | 可以承诺的工程产物 | 不可据此承诺 |
| --- | --- | --- |
| 综述草稿 | 章节装配、题录、论断映射、查询记录、局限、AI使用记录 | 穷尽文献、自动系统综述、投稿接收 |
| 用户提供真实实验材料的实证草稿 | 在字段与材料核验后整理Methods/Results，标缺失 | 为用户补造实验或认定研究有效 |
| 应用内部运行后写实验结果 | 执行/溯源契约完整后可支持 | “跑过程序”即满足科学方法 |
| 排版导出 | Markdown先行，按需求增加BibTeX/LaTeX/PDF适配 | 任意模板一两天无条件完成 |

当前题录身份链能提供书目信息核对，不等于完整语义证据链。摘要无法覆盖全文方法细节、统计假设和排除标准；语义审查与人工确认仍有缺口。不要保留原文“从生成稿到可核验稿没有断点”的绝对表述。

### 20.1 普通综述与系统综述

P1默认是专题综述。若未来支持系统综述，需要独立协议：完整可复现检索策略、来源与日期、纳入排除标准、去重与筛选日志、逐条排除理由、数据提取过程、适用的偏差评价、综合方法及流程统计，并如实披露人工和自动化参与方式。

PRISMA是报告指南；存在inclusion/exclusion字段不能自动宣称遵循。还需判断目标综述类型与适用扩展，不应把主要面向干预效果综述的条目不加区分套到全部CS任务。依据：[PRISMA 2020官方说明](https://www.prisma-statement.org/prisma-2020)、[适用范围说明](https://www.prisma-statement.org/)、[范围综述扩展](https://www.prisma-statement.org/scoping)。本文没有把某个固定筛选人数或检索词数量误写为所有系统综述的普遍硬规定。

### 20.2 写作与一致性

论文装配只用已发布论断、有效题录与验证结果。摘要、正文、表格、图注中的样本数、指标、单位、缩写与研究范围需相互一致；Limitations不能只把unsupported原样拼上去，必须保留具体缺失与其对结论的影响。

Results缺数据就标缺失，不生成“合理的”数字；引用的研究未读到全文时注明当前依据层级。保留作者决定、修改历史与AI参与记录，作者按目标期刊/会议最新政策核对披露、署名、数据与伦理要求。应用可提供提醒与检查清单，但不能代替作者承担投稿判断。

### 20.3 导出格式

先确保Markdown与机器可读研究包一致，再按需求增加BibTeX/LaTeX。PDF可由LaTeX、浏览器排版或其他受控渲染器实现，不是必须外部LaTeX；第一期未实现就明确不可用。

BibTeX键稳定、冲突可解析、特殊字符转义正确，不补造卷期页码；LaTeX/模板渲染禁用任意shell escape。导出文件引用包内相对路径、避免泄露用户名与本机目录。附件素材遵守其许可，不能因API公开访问就打包所有受版权保护正文。

## 23. 指标、回归与风险跟踪

### 23.1 可观测指标

本地可记录：每Profile启动/完成/证据不足/失败/取消次数；模型尝试与成功数；可选调用跳过原因；检索源成功/限流/空命中/缺摘要；首个阶段与整轮耗时；块隔离数；引用/片段定位比例；模型支持关系待审数；例题验证状态；预算中止与误停反馈。

### 23.2 核心风险登记

| 风险 | 当前控制 | 仍需承认的残余限制 |
| --- | --- | --- |
| 真实引用但语义错误 | 片段映射、支持关系审阅、人工直达来源 | 模型/人工仍可能误读 |

## 24. 最终建议与文档维护

建议批准原提案的**范围方向**，以本文替换其实现细节。优先级依次是：已有关键缺口修复 → 同源计划与预算 → 资料/论断快照和发布门禁 → 速查闭环 → 综述与教学 → 界面与历史收敛。暂缓任意执行、训练和自动论文成稿承诺。

| 教学（有资料） | scope/evidence/outline/sections/examples/final | C=2、正常7，上限7；追加尝试关闭 | 概念阶梯、带边界的类比、已验证范围内例题 |

这些是初始产品默认，不是所有任务的最优方案。开audit就至少为其增加1次必需额度；改C或N立即更新最少调用，保存时不自动突破用户原上限。

手算示例：P1 N=3，检索有材料，A=1，R=2，正常调用为3+5+1+2＝11；任何声称此配置“7–9次”的提示都是错误。P2 C=4且启用检索，正常9次；关闭检索且用户显式允许无资料教学才为8次。

## 附录 F. 首版数据契约与资源边界

本附录是实现必须覆盖的最小类型约束；**不是已经实现的JSON Schema文件**。M1需交付可执行Schema、纯校验器与迁移夹具后才可通过。提供商native-schema仅用受支持子集，最终仍执行本地完整Schema；无法返回合法结构时按已配置F处理，不悄悄切自由Markdown发布。

### F.1 类型和引用

| 类型 | 必需字段和约束 |
| --- | --- |
| ResearchConfigV4 | version=4，configSchemaRevision=1；profile/tier；活跃choices；retrieval/evidence/budget/monitor/mech/output；未知关键字段拒绝执行并给路径 |
| Choice | provider/model/effort三个非空规范字符串；来自目录；无effort模型用目录中的default，不用null冒充真实强度 |
| Template | planSchemaVersion、policyVersion、profile、有限nodes、条件、每节点角色/输入输出/后续保留；node依赖为有向无环图 |
| BoundPlan | templateHash、planHash、模型/连接版本、能力快照、有效限制；不含凭据 |
| SourceRecord | recordId、recordVersion、source/sourceId、字段来源、materialLevel、可空题录、来源观察、获取/复用信息 |
| Snippet | snippetId、record/version、字段、归一化版本、start/end、原切片文本/hash；先于调用生成 |
| Claim | 模型输入输出的localId/runRef分离；接纳后canonical claimId、text、kind、scope、limitations、evidence[]；系统生成review状态及hash绑定 |
| Block | 同样以localId接纳再映射canonical blockId；type、text或受信模板参数、显式local/run claimRefs/exampleRefs、dependsOnBlockIds；无悬空依赖或循环 |
| Example | exampleId、版本、givens及单位、assumptions、有限AST、expectedDisplay、rounding；本地计算结果单独写 |
| ReviewIssue | 对象ID、issueKind、snippetRefs、assessment、建议；不能自行修改对象或生成passed状态 |
| RunManifest | runId、userMessageId、parentRunId、配置/计划hash、状态、账本、对象hash、报告、提交版本；是发布事实源 |
| CommandResult | commandId、runId或error；幂等可重放本地返回结果，不重发远程请求 |

ID首版规范为 `[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}`；source引用别名S1…S240在run内解析。模型不得给路径当ID。存储路径由主进程映射生成，不直接拼接未经验证的renderer或模型字符串。

`additionalProperties:false`用于关键配置、权限、预算与可执行计划结构；展示用扩展元数据可保存在独立extensions对象，但不能影响执行。限制字段长度、数组长度、JSON深度和总大小，验证前不做原型对象合并。只接受有效UTF-8与JSON，拒绝重复关键键；如解析器不能报告重复键，需增加词法检查，不用JSON.parse最后键获胜作为安全语义。

### F.2 初始固定上限

| 对象/资源 | 首版上限与动作 |
| --- | --- |
| 用户问题 | 沿用现有1…50000字符；上下文仍受模型有效上限，超限不发 |
| 配置/IPC负载 | 每条256KiB，JSON深度32；超限本地拒绝 |
| 单模型文本输出 | 65536个UTF-16 code unit；流式累计即限制，超限取消、留截断状态，不发布半截 |
| 阶段结构 | 最多32claims、64blocks，每claim2048字符，每普通块4096字符；N≤4、C≤4不变 |
| 输入材料 | 最多40条记录、每条送入摘要最多2000字符；实际按模型输入容量减小，但必要依赖不可静默裁掉 |
| 资料库 | 每run最多240记录；接纳/送入/实际引用三者分别计数 |
| HTTP | 每响应流解码后2MiB、JSON深度64，重试计入maxRequests；XML无DTD/外部实体 |
| 算术 | §8.3统一限制；精确有理数，不加入另一份不同默认值 |
| 调用/并发 | 主≤24、机械≤4、合计≤24；模型并发默认2、最高4；所有桶与provider限制同时执行 |
| 本地保存 | run20MiB、对话100MiB的默认容量策略；可显式调整、不自动删历史 |

这些是产品初始防护参数，**不是研究充分性标准**，也不构成任何模型必定支持该上下文的承诺。模型目录有已验证token上限时按安全余量预检；未知时用适配器保守输入上限并显示unknown，服务端仍可能拒绝。不得为满足固定调用数擅自分批调用。

所有限制在统一policy对象定义，配置UI、主进程、Schema和测试读取同一版本。输入数量/长度上限可能使任务不能完成，应在发送前解释context_limit/output_limit，允许用户显式缩小范围；不把超限当成模型已经完整回答。

### F.3 错误协议

返回 `code/message/fieldPath/runId/nodeId/retryable/localAction`，敏感provider错误归一化，原始含Key/本机绝对路径内容不直接进toast。code至少覆盖：invalid_config、unsupported_version、model_unavailable、tier_unverified、context_limit、budget_insufficient、source_auth、source_unavailable、output_limit、invalid_artifact、evidence_insufficient、storage_failure、connection_changed、deadline_exceeded、user_cancel、interrupted。

retryable只说明可尝试新操作，不授权自动付费重试；localAction只能是UI可执行的固定枚举，如open_settings/show_process/new_run。模型diagnosis不能创造新动作。错误带runId不代表已生成科学答案。

- M1交付可执行Schema、纯模板/绑定器、统一预算调度、示例manifest和本地夹具；文档JSON只是示例，不能替代代码验证。
- 每个新能力至少一个成功路径、一个资源边界、一个失败恢复与一个旧数据用例；机械代理另有“关闭不影响核心”验证。
- 所有“已通过”对应证据文件、版本、测试ID和日期。模拟器检查只说明设计不变量自洽，不说明应用实现完成。

### G.2 残余不确定性如何处理

无法机械证明自然语言论断全部正确、检索穷尽、独立研究认定、题意与AST一致、远端真实停止或未来API永久可用。设计不以承诺消除它们，而以明确检查范围、未知状态、材料直达、人工审阅和拒绝越界实现控制。发现新反例需增加稳定测试ID并修订对应规则，不以既有问题清单作为关闭后续问题的理由。

本轮只修改设计文档、备份与检查记录。三档引擎、机械代理、Schema、T0隔离、存储重构及新增测试仍为待实现；旧有测试报告不能充当它们的通过证明。
