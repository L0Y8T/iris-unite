# 学习模式（教学档 P2）

一句话：**先真实检索资料，再拆知识点、算依赖图、排学习阶段、出带答案与判分口径的自测题。**

产出是一份**计划**，不是教程。它回答四个问题：先学什么、后学什么、每一步学完要能做到什么、怎么判断自己已经学会。

## 为什么不是"让模型一次性写一份学习计划"

一次性生成有两个绕不开的问题：

1. **顺序会变**。同一份知识点跑两次，模型给出的学习顺序可能不同。第二次打开发现路径变了，它就不是计划，是一次性回复。
2. **验不了**。模型把"学什么"和"先学什么"糊进同一段正文，错了只能整篇重来。

所以这里把「结构」和「文字」分开：

| 谁来做 | 做什么 |
|---|---|
| 模型 | 有哪些知识点、彼此谁依赖谁；每个阶段怎么学；每个知识点怎么测 |
| 程序（`core/learning.cjs`） | 连边、破环、拓扑分层、划分阶段、先修匹配、自测覆盖校验、确定性渲染 |

排序与分阶段全部由代码算，因此可复现、可测试、可解释。

## 流程

```
研究界定 → 资料检索 → 证据提取                      （沿用原有前三步）
   → 知识点拆解           1 次调用  模型只交"点 + 依赖"
   → 建图 / 破环 / 分层 / 分阶段    0 次调用  纯计算
   → 分阶段计划            C 次调用  每阶段一次，并行
   → 自测题设计            1 次调用
   → 整合成计划正文        1 次调用  沿用 research-final
   → 引用核验 / 终审自检            本地机械环节
```

模型调用数 = **C + 5**（有检索）或 **C + 4**（显式无资料教学），与 `docs/research-mode-design.md` §9.1 的公式一致。C 是学习阶段数，配置范围 2–4。

## 机械层做了什么

`core/learning.cjs` 是纯函数模块：不读文件、不发网络、不调模型。

| 步骤 | 规则 | 为什么必须机械 |
|---|---|---|
| 归一 | 补 id、去重名、难度落到 1–4、剔除资料库里不存在的引用键 | 模型的格式漂移很常见，一条坏数据不该废掉整张图 |
| 连边 | 断自环、断悬空先修（指向不存在的点），逐条留痕 | "先学它"指向空气，静默吞掉会让用户以为依赖满足了 |
| 破环 | 按原始顺序 DFS，删掉指回祖先的那条边 | 随机删一条会改变语义；删后向边保留书写顺序的直觉 |
| 分层 | 层号 = 1 + 依赖里最深的层号；同层按难度升序 | 层号直接决定"哪一层先学" |
| 先修匹配 | 用户声明「我已会 X」时，名称归一后互相包含即命中 | 宁可少匹配（多学一个已会的），不要错匹配（把没学的当已会，后面整段路径都塌） |
| 分阶段 | 拓扑序切成 C 个**连续块**，余数给靠后的阶段 | 拓扑序里每个点的依赖都排在它前面，所以连续块一定满足依赖 |
| 自测归一 | 指不回知识点的题直接丢 | 一道不知道该测什么的题，对学习者只是负担 |
| 校验 | 结构问题（漏排、空阶段、顺序违规）× 质量问题（覆盖缺口、无答案）分开 | 前者必须修，后者可以接受但要写进自检 |

所有自动修正都进 `kit.deviations`，最终渲染在计划末尾的「计划的自动修正」一节里。被修过什么、为什么修，用户能看见。

## 先修检查

配置里的「已具备的基础」是这个功能的唯一输入。命中规则保守：

- 归一后（小写、去空格与标点）互相包含，且长度 ≥ 2；
- 一条声明只吃掉一个知识点；
- 长度不足 2 的声明不参与匹配（单字太容易误命中）。

被命中的知识点**不进主路径**，但仍会保留一道自测题——声明只是声明，测一下才知道。

没匹配到任何知识点的声明不会被忽略，会以 `known-unmatched` 记进计划的「已知缺口」。

## 自测题

每个可学知识点一道，包含三样东西：

- `question`：优先「写出来 / 算出来 / 指出反例 / 解释为什么成立」；
- `answer`：参考答案要点，写清必须命中哪几条；
- `check`：判分口径——读者自己怎么判断做对了没有。

覆盖率由程序核，不靠模型保证。缺哪几个知识点会同时出现在自检面板和计划正文里。

## 什么时候明确失败

| 情况 | 行为 |
|---|---|
| 知识点拆解返回的不是可解析结构 | 停止本轮，报错并建议换模型 |
| 拆出 0 个知识点 | 停止本轮（主题通常太宽，需要改窄） |
| 某个阶段正文写坏（非 JSON） | 只降级那一段，原文进 `objective`，自检标注；结构不丢 |
| 自测题指不回知识点 | 丢弃该题，记一条 notice，覆盖率如实下降 |
| 知识点拆出的点少于 3 个 | 继续，但记 `few-points` 偏差提示路径过粗 |

这里刻意与实验族相反：实验跑不成要兜底继续（答案必须能说"没跑成"），而学习计划没有骨架就只剩一段泛泛而谈的建议——那种东西读起来像模像样，实际什么也没排，比明确失败更费用户时间。

## 配置

`researchConfig.teaching`：

| 字段 | 范围 | 说明 |
|---|---|---|
| `audience` | ≤ 80 字 | 学习对象 |
| `learningGoal` | ≤ 200 字 | 学习目标 |
| `prerequisites` | ≤ 12 条，每条 ≤ 60 字 | 已具备的基础，先修检查的输入 |
| `chapterCount` | 2–4 | **学习阶段数**。键名沿用原设计（分章正文），语义在此重写 |
| `maxPoints` | 3–30 | 知识点上限 |

界面里改阶段数会立刻改变基准调用数（阶段数就是分阶段写作的扇出），预览里能看到。

## 与 docs/research-mode-design.md §8 的关系

§8 描述的是「分章正文 + 例题算式校验」的完整教程。本期只做**学习计划**：

| §8 里的内容 | 本期状态 |
|---|---|
| 提纲 / 分章 / 例题三环节 | 保留环节 id，语义改为 知识点拆解 / 分阶段计划 / 自测题设计 |
| 分章正文（每章成篇讲解） | 不做。计划的产出是排程与自检，不是替代学习材料 |
| 例题数值预计算与冻结渲染 | 不做。自测题只要求答案要点与判分口径，不做算式核验 |
| 术语表、章节覆盖模型 | 保留字段（`chapterChoices`），本期未使用 |

三个环节 id、`PROFILE_STAGES['p2-teach']`、计划编译器的依赖表、预算公式都未改动——因此本次改造没有碰 `core/plan.cjs` 的图结构。
